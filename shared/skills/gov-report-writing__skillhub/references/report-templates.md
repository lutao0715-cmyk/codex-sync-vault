# 国央企常用报告模板框架

## 一、年度工作总结

```
一、主要工作及成效
    （一）[业务板块一]：成效概述 + 关键数据 + 典型案例
    （二）[业务板块二]：成效概述 + 关键数据 + 典型案例
    （三）[业务板块三]：成效概述 + 关键数据 + 典型案例

二、重点工作亮点
    （一）[亮点一]
    （二）[亮点二]
    （三）[亮点三]

三、存在的问题与不足
    （一）[问题一]：描述 + 原因分析
    （二）[问题二]：描述 + 原因分析
    （三）[问题三]：描述 + 原因分析

四、下一步工作计划
    （一）[目标一]：具体措施
    （二）[目标二]：具体措施
    （三）[目标三]：具体措施
```

### 写作要点
- 小标题对仗工整，多用动宾结构
- 数据具体化：增长率、完成率、同比增长等
- 问题分析不回避、不夸大、有对策
- 下一步计划要可量化、有时限、有责任人

    （一）[亮点一]
    （二）[亮点二]

    （一）理论学习深度不够
    （二）[业务方面不足]
    （三）[管理方面不足]

    （一）加强理论学习
    （二）提升业务能力
    （三）改进工作作风
```

### 写作要点
- 第一人称，语气谦逊务实
- 既不夸大成绩也不过分自贬
- 问题部分要体现反思深度
- 改进措施要具体可落实

    （一）[问题一]
    （二）[问题二]

    （一）[措施一]
    （二）[措施二]
    （三）[措施三]

### 写作要点

## 四、调研报告/课题研究

```
摘要（200字以内）

一、调研背景与目的
    1.1 政策背景
    1.2 调研目的
    1.3 调研方法（问卷/访谈/实地考察/数据采集）

二、现状分析
    2.1 基本情况
    2.2 主要特点
    2.3 数据呈现（可用表格）

三、存在的问题及原因分析
    3.1 [问题一]
        3.1.1 具体表现
        3.1.2 原因剖析
    3.2 [问题二]
    ...

四、对策建议
    4.1 [建议一]
    4.2 [建议二]
    4.3 [建议三]

五、结论与展望
```

### 写作要点
- 数据驱动，定性与定量结合
- 问题分析要有深度，不浮于表面
- 对策建议要可操作、有创新
- 引用权威数据源和政策文件
- 建议引用"十四五"规划、行业白皮书等权威依据

    （二）基本原则

二、主要任务
    （一）[任务一]
    （二）[任务二]
    （三）[任务三]

三、实施步骤
    （一）动员部署阶段（X月X日—X月X日）
    （二）全面推进阶段（X月X日—X月X日）
    （三）总结评估阶段（X月X日—X月X日）

四、责任分工
    （一）牵头部门：[XX部]，负责[XX]
    （二）配合部门：[XX部]，负责[XX]
    （三）监督部门：[XX部]，负责[XX]

    （一）组织保障
    （二）经费保障
    （三）技术保障

```

### 写作要点
- 目标要SMART（具体、可衡量、可达成、相关、有时限）
- 责任要落实到具体部门/个人
- 时间节点要明确
- 保障措施要具体，不说"加强领导"之类的空话

## 七、通知/公告

```
[发文机关标志]
[发文字号]

[标题]

[主送机关]：

[正文：事由 + 具体内容 + 要求]

附件：[附件名称]

[发文机关署名]
[成文日期]
（印章）
```

### 写作要点
- 开门见山，一事一通知
- 时间、地点、对象三要素必须明确
- 语言准确无歧义
- 命令性通知用语：必须、务必、不得
- 告知性通知用语：请、望、希

## 九、函

```
[发文机关标志]
[发文字号]

[标题]

[主送机关]：

[正文：缘由 + 事项 + 结语]

特此函告。
（或：专此函商。/ 请即函复。/ 特此函复。）

附件：[附件名称]

[发文机关署名]
[成文日期]
```

### 适用场景
- 去函：向平级或不相隶属机关商洽工作、询问问题
- 复函：答复对方来函所提问题
- 告知函：将有关事项告知对方

### 写作要点
- 一事一函，不夹杂多项不相关事务
- 语气平等谦和，不居高临下也不卑不亢
- 去函结语常用「请即函复」「盼复」；复函结语用「特此函复」
- 标题通常为「关于……的函」
- 正文开门见山，先写缘由再写事项

---

## 十、请示

```
[发文机关标志]
[发文字号]           签发人：[姓名]

[标题]

[主送机关]：

[正文：缘由 → 事项 → 结语]

妥否，请批示。
（或：以上请示如无不妥，请批准。/ 妥否，请审批。）

附件：[附件名称]

[发文机关署名]
[成文日期]
```

### 适用场景
- 请求上级对某项工作作出指示
- 请求上级批准某事项
- 请求上级解决具体困难

### 写作要点
- **一事一请**：一份请示只涉及一个事项，便于上级批复
- 缘由充分：说明为什么要请示，提供必要的背景和依据
- 方案明确：提出的意见或方案具体可操作
- 主送一个机关：请示只能主送一个上级机关
- 不得越级请示（特殊情况除外，须抄送被越过的机关）
- 「签发人」必须标注（上行文要求）
- 请示与报告的区分：请示需要批复，报告不需要

---

## 十一、批复

```
[发文机关标志]
[发文字号]

[标题]

[主送机关]：

[正文：引述来文 → 批复意见 → 结语]

此复。
（或：特此批复。）

[发文机关署名]
[成文日期]
```

### 适用场景
- 审批下级机关的请示事项
- 对下级的政策理解疑问作出解释

### 写作要点
- 开头必引用对方来文：你单位《关于……的请示》（文号）收悉。经研究，现批复如下：
- 态度明确：同意、原则同意、不同意，不可模棱两可
- 如部分同意，须说明不同意部分及理由
- 批复内容要有针对性，只回答请示中提出的问题
- 标题为「关于同意……的批复」或「关于……的批复」

---

## 十二、报告（行政公文类）

> 注：此处的「报告」指《党政机关公文处理工作条例》规定的 15 种法定公文之一，属上行文，区别于日常工作中广义的「报告」（调研报告、工作报告等，已在模板一至四中覆盖）。

```
[发文机关标志]
[发文字号]           签发人：[姓名]

[标题]

[主送机关]：

[正文：缘由 → 报告事项 → 结语]

特此报告。

附件：[附件名称]

[发文机关署名]
[成文日期]
```

### 适用场景
- 向上级机关汇报工作进展
- 反映某方面情况
- 答复上级机关的询问
- 向上级报送文件或物件

### 写作要点
- 「签发人」必须标注（上行文要求）
- 报告不得夹带请示事项（如需批复请用「请示」）
- 根据内容分为：工作报告、情况报告、答复报告、报送报告
- 工作报告：阶段性总结 + 下步计划
- 情况报告：发生了什么 + 怎么处理的 + 结果如何
- 答复报告：针对上级询问逐条回应
- 结语用「特此报告」，语气客观不卑不亢

---

## 十三、议案

```
[发文机关标志]
[发文字号]

[标题]

[主送机关]：

[正文：案由 → 方案 → 结语]

请审议。

附件：[附件名称]

[发文机关署名（盖章）]
[成文日期]
```

### 适用场景
- 各级人民政府向同级人大或其常委会提请审议事项
- 适用主体严格限定为政府机关，部门和个人不能使用

### 写作要点
- 使用范围极窄，仅限政府向人大提交
- 标题格式：「XX 人民政府关于提请审议……的议案」
- 正文：先说「为了……拟……」，再列出具体方案，最后「请审议」
- 附件通常是法规草案、人事任免名单等审议材料
- 成文日期为政府主要负责人签署日期

---

## 十四、决定

```
[发文机关标志]
[发文字号]

[标题]

[主送机关]：

[正文：缘由 → 决定事项 → 执行要求]

本决定自发布之日起施行。

附件：[附件名称]

[发文机关署名]
[成文日期]
```

### 适用场景
- 对重要事项作出决策部署
- 奖惩有关单位和人员
- 变更或撤销下级不适当的决定事项

### 写作要点
- 权威性强，用语果断、不容置疑
- 开头阐明决定的背景和依据（根据……，经……研究，决定如下：）
- 决定事项分条列出，条理清晰
- 涉及奖惩的决定，要写明依据和事实
- 执行要求明确时限和责任
- 标题通常为「关于……的决定」

---

## 十五、意见

```
[发文机关标志]
[发文字号]

[标题]

[主送机关]：

[正文：缘由 → 意见内容 → 结语]

以上意见，请结合实际情况贯彻执行。
（如无不妥，请批转各地各部门执行。/ 以上意见供参考。）

附件：[附件名称]

[发文机关署名]
[成文日期]
```

### 适用场景
- 对重要问题提出见解和处理办法
- 可用于上行、下行、平行，是公文中最灵活的文种

### 写作要点
- 方向灵活：上行意见→请求批转；下行意见→指导性文件；平行意见→参考建议
- 开头说明制定意见的背景、目的和依据
- 主体分条陈述具体意见，每条可含「原则要求 + 具体措施」
- 结语根据行文方向选择不同措辞
- 标题为「关于……的意见」或「关于……的实施意见」
- 下行意见可用「请认真贯彻执行」；上行意见多用「以上意见如无不妥，请批转」

## 二十六、超长报告分段生成策略

> 当报告预计超过 5000 字时，采用分段生成模式，避免单次输出质量下降。

### 策略流程

1. **先生成大纲**：与用户确认整体框架（一级标题 + 二级标题）
2. **逐章生成**：按章节顺序分批生成，每章 800-1500 字
3. **章末衔接**：每章结尾用过渡句为下一章做铺垫
4. **全文统稿**：所有章节完成后，整体通读，统一语言风格和措辞

### 用户提示

```
您要的报告预计约 [X] 字，建议分段生成以确保质量。
我将按以下顺序逐章完成：

第一章：[标题] （约 X 字）
第二章：[标题] （约 X 字）
……

现在开始第一章，完成后请您确认内容和方向，我继续下一章。
```

### 质量保障

- 每章生成后暂停，等待用户确认或修改意见
- 保持各章风格一致（同一套语气、用词、句式）
- 统稿时重点检查：标题对仗、数据一致性、逻辑连贯性

```
[发文机关标志：各联合发文单位名称，主办单位排列在前]

联合单位A
联合单位B

[主办机关发文字号]              签发人：[多签发人按序排列]

[标题]

[主送机关]：

[正文：缘由 → 事项 → 责任分工 → 结尾]

附件：[附件名称]

[发文机关署名：按版头顺序自上而下排列]
[成文日期：最后签发机关负责人签发日期]
（印章：按版头顺序排列，主办在前，互不相交相切）
```

### 适用场景
- 同级机关就共同事项联合发文（如多部门联合部署专项行动）
- 党委与政府联合行文部署全局性工作
- 不相隶属机关之间商洽、协调跨部门事项
- 多单位联合开展检查、整治、督查等专项工作

### 版头排列规则

联合行文的发文机关标志可并用各发文单位名称，也可单独使用主办单位名称。并用时按下列顺序排列：

| 联合类型 | 排列顺序 |
|---------|---------|
| 党委 + 政府 | 党委在前，政府在后 |
| 政府 + 军队机关 | 军队机关在前 |
| 行政机关 + 人民团体/事业单位 | 行政机关在前 |
| 同级同类机关 | 按编制序列或单位级别排列 |
| 跨级机关 | 级别高的在前 |

> **主办单位规则**：无论上述何种排列顺序，**主办单位一律排列在最前**。

### 发文字号与签发人

| 要素 | 规则 |
|------|------|
| 发文字号 | 只使用**主办机关**的发文字号，联合单位不另编发文字号 |
| 签发人（上行文） | 多个签发人按**发文单位排列顺序**，从左到右、自上而下编排 |
| 签发人排列格式 | 每行排两个姓名，回行时与上一行第一个签发人姓名对齐 |
| 成文日期 | 署**最后签发机关负责人**的签发日期 |

### 印章布局

联合行文一般应加盖**所有**发文单位印章，主办单位印章排列在前。

| 印章数量 | 排列方式 |
|:---:|---------|
| 2 个 | 左右并排，主办单位印章在左 |
| 3 个 | 上一下二（主办在上）或品字形排列 |
| 4-6 个 | 分两行排列，每行最多 3 个，主办在第一行首位 |
| 7 个以上 | 分三行及以上排列，保持行距均匀 |

**排列要求**：
- 印章之间**互不相交、不相切**，保持均匀间隔
- 印章用红色，端正清晰，不得倒置或倾斜
- 最后一个印章**居中下压**发文机关署名和成文日期
- 印章不得压住正文

### 写作要点
- 正文由**主办单位**牵头起草，联合单位会签确认，会签意见应充分吸纳
- 事项表述兼顾各联合单位职责边界，避免越权或职责交叉
- 涉及多家分工时，正文中明确"由 XX 牵头、XX 配合"的责任分工
- 结尾用语按行文方向选择：下行文用"特此通知"；上行文用"妥否，请批示"；平行文用"特此函告"
- 主送机关可并列多个，按级别或编制序列排列
- 版记中应标注所有联合发文单位

### 常见错误

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| 各联合单位各编发文字号 | 只使用主办机关发文字号 |
| 版头排列顺序错误（非主办单位在前） | 主办单位排列在最前 |
| 成文日期用最先签发日期 | 用最后签发机关负责人的签发日期 |
| 印章重叠或相交 | 印章互不相交、不相切，保持间隔 |
| 只盖主办单位印章 | 一般应加盖所有发文单位印章 |
| 联合单位职责表述交叉含糊 | 明确"牵头—配合"分工 |

## 三十三、转发性公文（转发 / 批转 / 印发）

```
[发文机关标志]

[发文字号]

[标题：关于转发《XXX》的通知]

[主送机关]：

现将《XXX》（XX〔2026〕X号）转发给你们，请结合实际认真贯彻执行。

（要求段：结合本单位实际提出具体要求，可分层列示）

附件：1.《XXX》
      2.《XXX》

[发文机关署名]
[成文日期]
（印章）
```

### 三类区分

| 类型 | 用于何种文件 | 被转发文件来源 | 标题格式 |
|------|------------|--------------|---------|
| **转发** | 将上级机关、不相隶属机关的文件转给下级或有关单位执行 | 上级机关 / 平级机关 / 不相隶属机关 | 关于转发《XXX》的通知 |
| **批转** | 将下级机关的请示、报告、意见等加注意见后转给其他单位参照执行 | 下级机关 | 关于批转《XXX》的通知 |
| **印发** | 将本机关或本机关办公厅（室）制定的文件下发执行 | 本机关自身 | 关于印发《XXX》的通知 |

**选用要点**：文件来自上级 → 转发；来自下级 → 批转；来自本单位 → 印发。
用错动词是转发性公文的典型硬伤，如把上级文件写成"批转"、把本单位文件写成"转发"。

### 标题与书名号规则

| 情形 | 写法 | 说明 |
|------|------|------|
| 标题直接嵌文件名 | 关于转发《XX公司关于XX工作的通知》的通知 | 外层标题不加书名号，内层用双书名号 |
| 被转发文件名本身含书名号 | 关于转发《XX公司关于印发〈XX管理办法〉的通知》的通知 | 嵌套时内层降为单书名号 |
| 原标题冗长含多层"的通知" | 关于转发《XX管理办法》的通知 | **可精简**，直接转发被转发文件的主体名称 |
| 多份文件一次转发 | 关于转发《XXX》《YYY》的通知 | 并列标注，书名号之间不加顿号 |

**标题精简原则**：不要照抄被转发文件的完整标题，出现"关于转发《关于印发〈XX〉的通知》的通知"这类三层嵌套即为不规范。
转发通知的标题应指向**被转发文件的实质内容**，而非其原文件形式。

### 正文结构（三段式）

```
第一段 · 引据
    现将《XXX》（XX〔2026〕X号）转发给你们，请结合实际认真贯彻执行。
    —— 必须完整引用被转发文件的名称与发文字号，文号用全角括号

第二段 · 要求（主体）
    结合本单位实际提出 2-4 条可操作要求，可分层列示：
    "一、……；二、……；三、……"
    也可点明责任分工："此项工作由 XX 部门牵头，XX 部门配合"

第三段 · 结语
    特此通知。
```

### 被转发文件的编排

| 项 | 规则 |
|----|------|
| 位置 | 附于转发通知之后，**另页起排**，不接写在通知正文下方 |
| 附件说明 | 转发性文件**可不写"附件"二字**（被转发文件属公文的组成部分而非附件）；若同时另附其他材料，则一并标注 |
| 版记处理 | 被转发文件**只转发主体**，其原发文机关的版记一般不随转发 |
| 密级处理 | 被转发文件带密级的，转发通知须按不低于原件的密级标注 |
| 页码 | 转发通知与被转发文件**统一连续编页** |
| 份号 | 转发通知按本单位规则编份号，被转发文件不另编 |

### 写作要点

- **转发通知要短**：不重复被转发文件的具体条款，只讲"谁来抓、怎么抓、何时报"
- **要求要实**：泛泛的"请认真贯彻落实"价值有限，应结合本单位实际明确时限、责任人、成果形式
- **主次要清**：转发通知是主件，被转发文件是随文下发的组成内容，不要在被转发文件中夹写本单位意见
- **一文一转**：原则上一次只转发一份主文件；确需同时转发的，应在标题中并列标注并说明相互关系
- **补充规定另行印发**：若本单位需配套实施细则，单独"关于印发《XX实施细则》的通知"，不与转发通知混写
- **结尾用语**：下行文用"特此通知"；如需反馈，加"请于 X 月 X 日前将落实情况报 XX"

### 常见错误

| 错误 | 正确 |
|------|------|
| 上级文件用"批转"、本单位文件用"转发" | 按来源选动词：上级→转发、下级→批转、本级→印发 |
| 标题三层嵌套"关于转发《关于印发〈XX〉的通知》的通知" | 精简为"关于转发《XX》的通知" |
| 正文不引被转发文件文号 | 完整引用"《XXX》（XX〔2026〕X号）"，文号用全角括号 |
| 被转发文件接写在通知正文下方 | 另页起排，统一编页 |
| 转发通知里大段重复被转发文件条款 | 只写落实要求，不重复原文 |
| 带密级文件转发时降低密级标注 | 转发通知密级不得低于被转发文件 |

## 三十四、请示批复联动（成对生成）

> 请示与批复是一组**对应行文**：下级请示、上级批复，事项一一对应。
> 本节的用法是**成对生成**——给出一个事项，先出请示，再据请示出批复，两稿要素自动对应。

### 请示框架

```
[发文机关标志]

[发文字号]

关于XXX的请示

[主送机关]（一个，且为直接上级机关）：

[第一段 · 缘由]
    为什么要请示：背景、依据、现状、遇到的问题

[第二段 · 事项]
    具体请求什么：请求批准 / 请求指示 / 请求解决的具体事项

[第三段 · 结语]
    妥否，请批示。
    （或：以上请示，如无不妥，请批准。）

[发文机关署名]
[成文日期]
（印章）
```

### 批复框架

```
[发文机关标志]

[发文字号]

关于XXX的批复

[主送机关]（即请示单位）：

你单位《关于XXX的请示》（XX〔2026〕X号）收悉。经研究，现批复如下：

[第一段 · 表态]
    同意 / 原则同意 / 不同意，须先明确表态再讲条件

[第二段 · 事项回应]
    对请示事项逐项回应，必要时明确执行标准、期限、责任

[第三段 · 结语]
    此复。

[发文机关署名]
[成文日期]
（印章）
```

### 要素对应关系（联动的核心）

| 要素 | 请示 | 批复 |
|------|------|------|
| 发文机关 | 下级单位 | 上级机关 |
| 主送机关 | 上级机关（**一个**，直接上级） | 请示单位（即原发文机关） |
| 标题 | 关于XXX的请示 | 关于XXX的批复（**事由表述须一致**） |
| 发文字号 | 请示单位自编，正文外 | 批复机关自编；**批复正文须引用请示文号** |
| 请求事项 | 一事一请 | 逐项回应，不得漏项 |
| 行文方向 | 上行文 | 下行文 |
| 日期 | 请示在前 | 批复在后，不得倒置 |
| 结束语 | 妥否，请批示 / 请予批准 | 此复。 |

**联动校验四项**（生成两稿后必须核对）：
1. 标题中的事由完全对应（"关于 XX 经费的请示" ↔ "关于 XX 经费的批复"）
2. 批复引据的请示文号与标题，与请示稿**逐字一致**
3. 批复主送机关 = 请示发文机关；批复发文机关 = 请示主送机关（双向互换）
4. 批复表态覆盖请示的全部请求事项，无遗漏、无超范围

### 三种批复表态

| 表态 | 适用情形 | 表述式样 |
|------|---------|---------|
| **同意** | 请示事项合规可行，无附加条件 | "同意你单位……。请按有关规定办理。" |
| **原则同意** | 总体可行但需调整或强调若干事项 | "原则同意你单位……。同时，请注意以下事项：一、……二、……" |
| **不同意** | 事项不合规、条件不具备或超越权限 | "不同意……。理由是：……。建议……" |

> **表态必须前置**：批复第一句就要给出明确态度，不得先讲一堆背景再表态。
> 不同意时须说明理由并给出替代建议，不能只回一个"不同意"。

### 写作要点

- **请示一文一事**：一份请示只涉及一个事项，便于上级明确批复；事项混杂会被退回
- **请示只报一个主送机关**：不得多头请示；确需其他机关知晓的，用"抄送"
- **不得越级请示**：特殊情况越级请示的，须同时抄送被越过的机关
- **请示与报告不得混用**：报告中不得夹带请示事项（需批复的必须用"请示"）
- **批复须有据**：引述请示时应写明请示的标题与发文字号，不用"来文收悉"草率带过
- **批复不得超范围**：只回应请示中提出的事项，不擅自增加新的工作要求
- **时限概念**：批复通常应在收到请示后及时办理，行文中如涉及时限应一并明确

### 常见错误

| 错误 | 正确 |
|------|------|
| 一份请示写三件事 | 一文一事，分三份请示 |
| 请示同时报两个上级机关 | 只报一个主送机关，其余抄送 |
| 报告中夹带请示事项 | 需批复的改用"请示"文种 |
| 批复未引用请示文号 | 写明"你单位《关于XX的请示》（XX〔2026〕X号）收悉" |
| 批复先讲背景后表态 | 首句明确表态，再讲条件 |
| 批复标题事由与请示不一致 | 两份标题事由逐字对应 |
| 批复日期早于请示日期 | 日期必须请示在前、批复在后 |
| 用"特此批复"作结束语 | 批复的规范结束语是"此复。" |

## 三十五、制度 / 办法 / 标准类（规章制度类文件）

> **模板锚点：templates#35**
> 适用于：管理办法、暂行办法、实施细则、工作细则、操作规程、管理标准、
> 准入标准、考核办法、议事规则、章程、工作规范。

### 适用场景

| 用户说法 | 对应文种 | 说明 |
|---------|---------|------|
| "定个管理办法""出台制度" | **办法 / 制度** | 对某项工作作出具体规定 |
| "试试看先跑一段" | **暂行办法** | 需在文末注明试行期限或不注期限而由发布机关掌握 |
| "把上级文件细化成我们自己的规定" | **实施细则** | 必须写明依据的上位文件（全称 + 文号） |
| "定个标准""准入条件""门槛" | **标准 / 准入标准** | 以条件条款为主，须可判定、可量化 |
| "定个操作流程" | **操作规程 / 工作细则** | 以步骤、时限、责任为主 |
| "定个议事规则" | **议事规则 / 章程** | 侧重组织、程序、表决方式 |

### 四类文件的取向差异（选错文种是硬伤）

| 文种 | 回答的问题 | 条款特征 |
|------|-----------|---------|
| **制度 / 办法** | "这件事按什么规则办" | 规则性，含职责分工与责任追究 |
| **标准 / 准入标准** | "达到什么条件才算合格" | 条件性，尽量量化、可判定 |
| **细则 / 操作规程** | "具体每一步怎么做" | 程序性，含步骤、时限、表单 |
| **章程 / 议事规则** | "这个组织怎么运转" | 组织性，含组成、职权、表决 |

> **易混提醒**：**办法 ≠ 方案**。方案回答"这一次怎么干"（一次性、有起止），
> 办法回答"以后都怎么办"（长期有效、可反复适用）。写"实施方案"不要写成"办法"体例。

### 结构框架（两种体例，择一）

**体例一：章条式（内容多、层次深时用）**

```
标题：××单位××管理办法

第一章  总则
       第一条 【制定目的与依据】为……，根据《上位文件全称》（发文字号），制定本办法。
       第二条 【适用范围】本办法适用于……。
       第三条 【基本原则】……应当遵循……的原则。
第二章  职责分工
       第四条 【主管部门】××部门负责……。
       第五条 【配合部门】××部门负责……。
第三章  管理内容（可按业务环节拆若干章，每章管一件事）
       第六条 ……
       ……
第四章  监督与考核
       第X条 【监督检查】……每年度至少检查一次。
       第X条 【责任追究】对……的，依照……追究责任。
第五章  附则
       第X条 【解释机关】本办法由××部门负责解释。
       第X条 【施行日期】本办法自××年××月××日起施行。
       第X条 【废止条款】此前发布的相关规定与本办法不一致的，以本办法为准。
```

**体例二：条文式（内容少、不设章时用）**

```
标题：××单位××管理规定

第一条 ……
第二条 ……
……
第X条 本规定由××部门负责解释，自××年××月××日起施行。
```

### 写作要点

1. **上位依据必须写全**：细则、办法的开头必须写明依据的上位文件**全称与发文字号**；
   查不到原文时用缓冲表述并列入待补清单（见 `policy-citation-guide.md`），**不得凭印象补文号**。
2. **条文"一条一事"**：一条只规定一件事。一条里塞三件事，执行时必然扯皮。
   内容多的拆条，不拆段。
3. **条款句式统一**：一律用"应当 / 不得 / 可以 / 负责 / 由……负责"。
   - "应当"= 义务性（必须做）
   - "不得"= 禁止性
   - "可以"= 授权性
   - 避免"要求……""希望……""原则上……"——**制度里不要出现"原则上"**，要么禁止要么允许。
4. **可判定**：条款要能被判定"做到了没有"。写"学历应当较高"无法判定；
   写"须具有硕士研究生及以上学历"可判定。**能量化就量化**。
5. **不设主送机关**：制度正文本身不写主送机关、不盖章——这两项由随附的**发布通知**承担。
6. **附则必含三项**：解释机关、施行日期、与原规定的衔接（废止/不一致处理）。
7. **数词与序号**：条文序号用"第X条"通篇连续编号（**章断条连**，不因换章重新从第一条开始）；
   条内分款用"（一）（二）（三）"，款内分项用"1. 2. 3."。
8. **有效期与试行**：暂行办法应写明试行期限（如"试行期一年"）；
   有明确期限的（如五年规划配套办法）宜在附则注明有效期。
9. **与其他文件的衔接**：多份制度并存时，必须写明"不一致的以本办法为准"，
   否则执行时会被问"到底听哪份的"。

### 常见错误

| 错误 | 正确 |
|------|------|
| 依据只写"根据国家有关规定" | 写明上位文件全称与发文字号，查不到则用缓冲表述并标注待核 |
| 一条里规定三件事 | 一条一事，拆条 |
| 用"原则上应当……" | 制度中不出现"原则上"：要么"应当"，要么"不得" |
| 条款不可判定（"学历较高"） | 量化（"硕士研究生及以上学历"） |
| 换章后条号重新从"第一条"开始 | 章断条连，全篇连续编号 |
| 附则缺施行日期 | 附则必含解释机关 + 施行日期 + 衔接条款 |
| 正文写主送机关、盖印章 | 制度正文不写主送、不盖章，由发布通知承担 |
| 与旧规定冲突却不作说明 | 附则写明"不一致的以本办法为准" |
| 把"实施方案"写成"办法" | 一次性工作用"方案"，长期规则用"办法" |
| 细则不引用上位文件 | 细则必须写明依据的上位文件全称与文号 |

### 与发布通知的配套

制度类文件通常**成对发布**：一份**发布通知**（有主送机关、有印章、有发文字号）
+ 一份**制度正文**（作为附件随文下发）。

- 用户只要制度正文 → 按本节写，交付时提示"发布时需另配发布通知"
- 用户要完整发文 → 用「通知」模板 + 本节制度正文，制度正文作为附件另页起排

### 质量评分提示

`scripts/quality_score.py` 已支持 `--type 制度标准`：
该类型**豁免"主送机关"与"印章"两项必备要素**，章节校验按
「总则 → 职责分工 → 管理内容 → 监督考核 → 附则」五段判定。
不指定类型时也可自动识别（标题含"制度/办法/标准/规范/细则/规程"即命中）。

## 三十六、文种易混辨析（选错文种 = 从根上错）

> **为什么单列一节**：文种选错时，格式再规范、语句再漂亮也是废稿——
> 请示写成报告会耽误审批，报告夹带请示事项会被退回，通知与通报混用
> 会削弱效力。**下笔前先定文种，定不下来就查本节。**

### 36.1 五组高频易混对照

| # | 易混对 | 核心差别 | 判定口诀 | 典型误用 |
|:-:|--------|----------|----------|----------|
| 1 | **请示 vs 报告** | 请示**要回复**（事先）；报告**不要回复**（事中/事后） | 请示"求批准"，报告"使知晓" | 报告末尾写"妥否请批示"→ 退回 |
| 2 | **通知 vs 通报** | 通知**布置工作**（要求去做）；通报**告知情况**（表彰/批评/传达） | 通知管"要做什么"，通报管"发生了什么" | 表彰先进用"通知"→ 效力弱 |
| 3 | **批复 vs 意见** | 批复**针对单个请示**、被动答复；意见**面向普遍问题**、可主动下发 | 批复"一对一"，意见"一对多" | 答复请示用"意见"→ 无对应性 |
| 4 | **函 vs 通知** | 函用于**平级/不相隶属**单位；通知用于**下行**或本单位内部 | 平级用函，下行为通知 | 向平级单位发"通知"→ 越权 |
| 5 | **决定 vs 决议** | 决定为**领导机关**作出；决议须经**会议讨论通过** | 会议表决用决议，领导拍板用决定 | 领导班子决定写成"决议"→ 程序不符 |

### 36.2 一句话选文种（决策树）

```
要不要对方回话？
├─ 要（求批准/答复）→ 对方是上级？→ 请示
│                    └ 对方是平级？→ 函
├─ 不要，只是告知
│   ├ 告知"要做什么事" → 下行/内部 → 通知
│   ├ 告知"发生了什么事" → 通知范围之外 → 通报
│   └ 答复别人的请示 → 批复
└─ 面向不特定对象、讲原则办法 → 意见
```

### 36.3 三个致命错误（一旦出现必须重写）

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| **报告夹带请示事项** | 上级可能因"报告不答复"而不处理该事项 | 拆成两份：事项性内容走「请示」，情况性内容走「报告」 |
| **请示一文多事** | 一事未批准则全文搁置，且不便归档 | 一事一请示，确需同时报的多事项拆成多个请示 |
| **越级请示** | 违反行文规则，通常不予受理 | 逐级上报；确需越级的，同时抄送被越过的机关 |

### 36.4 与 `quality_score.py` 的联动

`scripts/quality_score.py` 在「规范度 → 公文规范」项下已内置两条检测：

- `（报告|汇报）……（请批示|请审批|请批准）` → 扣 2 分，提示"报告不得夹带请示事项"
- `请示……（同时|另外|此外）……（请|拟）` → 扣 1 分，提示"请示应一事一请"

**注意**：脚本只查上述两条**字面可判**的错误。「函用于平级」「决定 vs 决议」
这类**需要判断单位关系与会议程序**的，机器无法核验——**必须人工确认**。

## 三十七、通报

> **与「通知」的分界（先看这条）**：通知布置工作（要你去做），通报告知情况（告诉你发生了什么）。
> 表彰先进、批评错误、传达重要情况，一律用**通报**；用「通知」表彰会削弱效力（见 §36.1 第 2 组）。

### 适用场景

| 类型 | 用途 | 典型事由 |
|------|------|----------|
| **表彰性通报** | 表扬先进、推广经验 | 「关于表彰 2025 年度安全生产先进集体和个人的通报」 |
| **批评性通报** | 指出问题、警示他人 | 「关于 XX 单位违规操作问题的通报」 |
| **情况通报** | 传达重要情况、工作进展 | 「关于上半年重点任务推进情况的通报」 |

### 结构框架

```
关于XXX的通报

主送机关（可省略，视知悉范围而定）：

〔导语〕近期，我单位……（交代事由、时间、范围）

一、主要情况 / 先进事迹 / 问题事实
   （摆事实。表彰类写清事迹与成效，批评类写清事实与危害，
     情况类写清进展与数据。均需有据可查，不空泛评价。）

二、评价与定性
   （表彰类：肯定意义、精神；批评类：指出性质、危害；
     情况类：判断形势、明确要求。此段是通报的"魂"，不可缺。）

三、决定 / 要求
   （表彰类：作出表彰决定，明确奖励内容；
     批评类：提出处理意见，明确整改要求与期限；
     情况类：提出下一步工作要求。）

特此通报。

                    发文机关署名
                    成文日期
```

### 写作要点

- **事实必须确凿**。批评性通报尤其要经得起核对，事实不清、定性不准会引发争议甚至复议。
- **表彰决定要具体**。写清给什么奖励（记功/授予称号/奖金），不写"给予表彰"就完事。
- **批评类通报注意分寸**。就事论事，不扩大化、不涉及无关人员信息；涉及个人的一般以「XX 单位 XXX」形式，必要时匿名化。
- **通报不写"请批示"**。它是告知性文种，不需要对方回复。
- **涉密与隐私**：批评性通报若涉及具体人员，须确认可公开范围；涉密内容按密级标注。

### 常见错误

| 错误 | 正确 |
|------|------|
| 表彰先进用「通知」 | 用「通报」（通报的功能之一就是表彰） |
| 通报表彰只写"给予表彰" | 写清奖励种类与内容 |
| 批评性通报大段议论、缺少事实 | 先用事实说话，再作评价定性 |
| 通报末尾写"妥否，请批示" | 通报是告知性文种，用「特此通报。」收束 |
| 情况通报只报喜不报忧 | 如实反映进展与问题，否则失去通报意义 |

## 三十八、公示

> **公示 ≠ 公告 ≠ 通知**。公示是把**拟作出的决定或拟确认的事项**公开出来，
> 在**特定期限内**征求异议，核心特征是**有异议期**。没有异议期的不叫公示。

### 适用场景

| 场景 | 典型事由 |
|------|----------|
| **干部任前公示** | 「关于 XX 同志拟任职务的公示」 |
| **评优评先公示** | 「关于 2025 年度先进集体和先进个人评选结果的公示」 |
| **招录招聘公示** | 「关于 2025 年公开招聘拟录用人员的公示」 |
| **职称评审公示** | 「关于 2025 年度职称评审通过人员名单的公示」 |

### 结构框架

```
关于XXX的公示

根据《XXX》（XX〔2026〕X号）有关规定，经XXX研究决定，
现将XXX予以公示：

一、公示对象
   （逐项列明。人员类：姓名、性别、出生年月、现任职务、拟任职务；
     或姓名、单位、职称、评审结果。名单类：单位名称、事由、金额等。）
   1. XXX，男，1985 年 X 月生，现任 XXX，拟任 XXX。
   2. XXX，女，1990 年 X 月生，现任 XXX，拟任 XXX。

二、公示时间
   2026 年 X 月 X 日至 X 月 X 日，共 X 个工作日。

三、异议方式
   公示期间，如对公示对象有异议，可通过来信、来电、来访等形式
   向 XXX 反映。反映情况要实事求是、客观公正，并提供联系方式，
   以便调查核实。我们对反映人和反映情况严格保密。
   联系电话：XXX；电子邮箱：XXX；通讯地址：XXX。。
   受理时间：工作日上午 9:00-11:30，下午 14:00-17:00。

                    发文机关署名
                    成文日期
```

### 写作要点

- **公示期必须写明**。这是公示的法定要素，一般 5-7 个工作日，具体按制度规定。写成"近期公示"等于无效公示。
- **异议渠道必须具体**。电话、邮箱、地址、受理时间至少给两项，且必须是真实可用的。
- **公示对象信息要完整但克制**。干部公示按规定的项目列，不多列身份证号、家庭住址等非必要信息。
- **不得同时写"最终结果"**。公示是拟定的、待确认的，措辞用「拟任」「拟录用」「拟推荐」，不能用「决定任命」。
- **保密与合规**：涉及个人信息公开，须确认符合个人信息保护要求；只公开公示必需项目。

### 常见错误

| 错误 | 正确 |
|------|------|
| 未写公示期限 | 必须写明起止日期与工作日数 |
| 异议渠道留空或写"另行通知" | 给具体电话/邮箱/地址，且真实有效 |
| 用「决定任命」等已完成时态 | 用「拟任」「拟录用」等待定时态 |
| 公示对象信息过度，含身份证号、住址 | 只列公示必需项目 |
| 公示期未满即发布正式任职通知 | 公示期满无异议后方可办理 |

## 三十九、感谢信与贺信

> **同属礼仪性文书，对象与时机不同**。感谢信用于**事后致谢**，
> 贺信用于**事前/事中道贺**。两者格式相近，语气均须真诚克制，
> 最忌空泛套话堆砌。

### 适用场景

| 文种 | 时机 | 对象 |
|------|------|------|
| **感谢信** | 事后 | 给予本单位帮助、支持的外部单位或个人 |
| **贺信** | 事前或事中 | 兄弟单位重大活动、重要纪念日、重要成就 |

### 感谢信框架

```
感谢信

XXX（受信方）：

〔事由〕XXXX 年 X 月，我单位在XXX工作中，得到贵单位的大力支持。
（具体写清何时、何事、对方做了什么，忌笼统）

〔意义〕贵单位XXX（具体行动，如"选派 5 名技术骨干驻场支援"），
为我单位顺利完成XXX任务提供了有力保障。这种XXX的精神，
值得我们学习。（点出对方行为的具体价值，不空喊"感谢"）

〔致谢与展望〕在此，谨向贵单位及参与支持工作的全体同志
表示衷心感谢！期待今后继续加强合作，共同XXX。

此致

敬礼！

                    XXX（发信方全称）
                    XXXX 年 X 月 X 日
```

### 贺信框架

```
贺信

XXX（受信方）：

值此XXX之际，谨向你们表示热烈祝贺，并向XXX（相关群体）
致以诚挚问候！

〔成就肯定〕贵单位XXX（具体成绩、数据、突破）。这些成绩的取得，
是XXX的结果，凝聚着XXX的心血。（有具体内容，不空泛）

〔意义与期待〕XXX 对XXX具有重要意义。衷心祝愿贵单位
在今后XXX中取得新的更大成绩，期待我们进一步深化合作，
共同为XXX作出新的贡献。

此致

敬礼！

                    XXX（发信方全称）
                    XXXX 年 X 月 X 日
```

### 写作要点

- **必须有具体事由**。写清「什么时候、对方做了什么、帮到了什么」，笼统的"大力支持"等于没写。
- **篇幅宜短**。感谢信、贺信一般一页以内，300-600 字为宜，长了反而失礼。
- **语气真诚克制**。不用夸张形容词（"极其伟大""无与伦比"），不用过度排比。
- **署名用单位全称**。礼仪文书一般以单位名义发出，不用个人名义（除非确属个人致谢）。
- **「此致敬礼」的格式**：`此致` 空两格或顶格均可，`敬礼！` 另起一行顶格，这是书信体惯例。
- **贺信称谓**：可写单位名，也可写「XXX 单位全体同志」，视场合而定。

### 常见错误

| 错误 | 正确 |
|------|------|
| 通篇"感谢感谢"，无具体事由 | 写清何时何事、对方做了什么 |
| 感谢信写成了工作汇报 | 主体是致谢，工作成效只作背景带过 |
| 贺信只写"祝贺"不写成绩 | 肯定具体成就，才有分量 |
| 署名用个人姓名 | 一般用单位全称 |
| 篇幅过长（超两页） | 控制在 300-600 字 |
| 「此致」「敬礼」排在同一行 | 「敬礼！」另起一行顶格 |

## 四十、会议方案

> **会议方案 ≠ 会议议程 ≠ 会议纪要**。方案是**会前**的筹备设计（怎么办），
> 议程是会议**程序安排**（按什么顺序进行，见 §二十九），纪要是**会后**的结果记录（见 §六）。
> 三者时间位置不同，不可互相替代。

### 适用场景

- 大型会议（年度工作会、职代会、表彰大会）会前报批
- 需要多部门协同筹备的专题会议
- 需要明确经费、场地、人员分工的会议

### 结构框架

```
XXX会议方案

一、会议名称
   XXX（全称，含年度、届次等要素）

二、会议主题 / 主要任务
   以XXX为指导，围绕XXX，总结XXX，部署XXX。
   （明确本次会议要解决什么问题，一两句说清）

三、会议时间
   XXXX 年 X 月 X 日（星期X）上午 9:00，会期 X 天。

四、会议地点
   XXX（具体到会议室名称）

五、参会人员
   1. 出席：XXX（范围与人数，如"公司领导班子成员，各部门主要负责人"）
   2. 列席：XXX
   3. 特邀：XXX
   共计约 XXX 人。

六、会议议程
   主持人：XXX
   1. 9:00-9:30  XXX 作XXX工作报告
   2. 9:30-10:30 XXX 专题发言（XXX、XXX 单位）
   3. 10:30-11:00 分组讨论
   4. 11:00-11:30 XXX 总结讲话
   （逐项写明时间、内容、主讲人）

七、筹备分工
   | 事项 | 责任部门 | 责任人 | 完成时限 |
   |------|---------|--------|---------|
   | 会务组织、通知发放 | 办公室 | XXX | 会前 3 天 |
   | 材料准备、印制 | XXX 部 | XXX | 会前 2 天 |
   | 会场布置、设备调试 | XXX 部 | XXX | 会前 1 天 |
   | 签到、记录、宣传 | XXX 部 | XXX | 会议当天 |
   | 后勤保障、经费 | XXX 部 | XXX | 会前 1 天 |

八、有关要求
   1. 参会人员提前 15 分钟入场，不得无故缺席。
   2. 会议材料于会前 X 日汇总至XXX部。
   3. 严格遵守会议纪律，手机调至静音。
   4. 涉密内容按保密规定管理。

九、经费预算（如需报批）
   预计 XXX 元，列支渠道：XXX。

                    拟制部门：XXX
                    拟制日期：XXXX 年 X 月 X 日
```

### 写作要点

- **九大要素齐全**。名称、主题、时间、地点、人员、议程、分工、要求、经费，缺一项都会导致执行时扯皮。
- **筹备分工必须落到人和时限**。写"相关部门负责"等于没分工，必须「责任部门 + 责任人 + 完成时限」三要素齐备。
- **议程要卡时间**。每项给起止时间，总时长与会议时长对齐，别出现"议程 3 小时、会议开 2 小时"。
- **会议名称要完整**。含年度、届次、单位层级，不用简称（正式方案中首次出现应用全称）。
- **报批与执行区分**：需上级批准的写「以上方案，妥否，请批示」；内部执行的可省略报批语。
- **涉密会议**：涉及涉密内容的，须在方案中明确保密要求与参会人员范围审批。

### 常见错误

| 错误 | 正确 |
|------|------|
| 只有议程没有分工 | 加"筹备分工"表，落实到部门、人、时限 |
| 议程不标时间 | 每项标注起止时间，与会议总时长对齐 |
| 参会范围写"相关人员" | 明确到职务层级或具体单位，并给出人数 |
| 把会议方案写成会议议程 | 方案含筹备、分工、经费；议程只是其中一项 |
| 经费预算留空 | 需报批的会议必须列出预算与列支渠道 |
| 未明确主持人 | 议程中写明主持人姓名与职务 |
