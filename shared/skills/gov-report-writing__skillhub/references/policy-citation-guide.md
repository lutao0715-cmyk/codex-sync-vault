# 政策引用溯源规范

> 定位：解决"公文里的政策依据说不清出处"这个问题。
> 与 `policy-database.md`（常用文件速查）、SKILL.md **E11**（政策文件不存在时的处置）配套使用。
> **边界声明**：本 Skill **不联网**，因此这里的"溯源"指的是——
> **把引用写规范、把要素补齐、把待核对项列清楚**，
> 而不是替用户验证文件是否存在。事实核验必须由用户比对官方原文。

---

## 一、为什么溯源是公文写作的高风险项

公文与一般文章最大的区别：**每一个政策依据都要能被审核人查证**。

| 风险 | 后果 |
|------|------|
| 文件名写错一个字 | 审核时被退回，严重时被认定为"引用失实" |
| 文号编造或记错 | 属于**实质性错误**，可能触发问责 |
| 引用了已废止的文件 | 整段论证失效，需推倒重写 |
| 引用了外省政策作为本省依据 | 口径错误，比找不到依据更严重 |
| 只写"根据有关文件" | 看似安全，实际是**没有依据**，审核无法通过 |

> **判断标准**：一份公文里的政策引用，应该达到"审核人拿着文号就能在官网搜到原文"的程度。
> 达不到的，要么补齐，要么明确标注待核，**不能含混过去**。

## 二、引用格式标准

### 2.1 基本式样

```
根据《文件全称》（发文字号，发布日期）精神……
```

**完整示例**：

```
根据《政务移动互联网应用程序规范化管理办法》（国办函〔2026〕12号，2026年1月15日）要求，
现就有关事项通知如下。
```

**简化式样**（句内引用，不打断文气时用）：

```
根据《政务移动互联网应用程序规范化管理办法》（国办函〔2026〕12号）要求……
```

### 2.2 四种标识类型的写法

| 类型 | 式样 | 示例 | 是否需补发布日期 |
|------|------|------|:---:|
| **〔〕式发文字号** | 机关代字 + 〔年份〕 + 序号 + 号 | `国办发〔2026〕12号` | 建议补 |
| **令式文号** | 机关 + 令 + 第X号 | `主席令第二十八号` / `国务院令第765号` | **必须补**（令号不含年份，不补则无法定位） |
| **标准编号** | 标准代号 + 编号 + 年份 | `GB/T 9704-2012` / `DB11/T 1234-2025` | 年份已内含，无需另补 |
| **法律法规** | 全称 + 通过/修订日期 | `《中华人民共和国劳动法》（2018年修正）` | 建议标注版本 |

> **注意**：六角括号是 `〔〕`（U+3014/U+3015），**不是** `[` `]` `（` `）` `【` `】`。
> 这是国标格式的硬要求，也是公文审核的高频扣分点。可用 `scripts/policy_cite.py` 自动检出。

### 2.3 首引与后续

| 位置 | 写法 |
|------|------|
| 首次引用 | **必须用文件全称**，加书名号，附文号 |
| 后续引用 | 可用「该文件」「该意见」「上述办法」等指代 |
| 同一文件多次引用 | 名称写法须**前后完全一致**，不得一处全称一处简称混用 |

> 混用两种写法，会被理解成**两份不同的文件**。`policy_cite.py` 会检出这类问题。

## 三、来源优先级（核对原文时按此顺序）

| 优先级 | 来源 | 说明 |
|:---:|------|------|
| ① | **中国政府网 / 国务院政策文件库** | `www.gov.cn`，国务院及国办文件的权威出处 |
| ② | **部委官网** | 认准 `.gov.cn` 域名与官方发布栏目 |
| ③ | **省级政府官网 / 地方政策法规库** | 地方性文件的权威出处 |
| ④ | **人民日报 / 新华社** | 权威媒体报道，可佐证口径，**但正式引用仍应回到原文** |

**不要用作依据的来源**：商业数据库转载、自媒体解读、培训机构整理的"政策汇编"、
AI 生成的摘要——这些可以作为查找线索，**不能作为引用依据**。

> **红线**：**严禁将外省政策作为本省政策依据**。
> 地方性政策的适用范围有严格的地域界限，跨省引用属实质性错误。

## 四、时效性核验（四步）

引用前对每一份文件跑一遍：

1. **看发布日期与生效日期**——注意区分"印发日"与"施行日"，文中指的是哪一个要写清。
2. **查是否被修订**——同一文件常有多个版本，确认引用的是**现行有效版本**。
3. **查是否已废止**——重点看有没有"废止××"类通知。失效文件不得作为依据。
4. **看时段性**——对"十四五""三年行动"等**有明确期限**的政策，
   确认当前是否仍在有效期内；跨期引用要写清"延续执行"。

> **判断口径**：政策名称、文号、发布日期、精确数字这几项，
> **只有来源明确且口径一致时**才写成确定结论；否则降级为概括表述或标注待核。

## 四·补、人工核验三步清单（Y-6：交付前逐条走一遍）

> **这一节解决评测里的这句话**："涉及具体政策内容的事实准确性，主要还是靠你自己核对"。
> 脚本能查格式，查不了真假。所以给出**一份可直接照做的核验流程**——
> 每处引用 3 步、每步 30 秒到 2 分钟，按引用条数线性累加。

### 第一步：查存在（"这份文件真的有吗"）

| 动作 | 具体怎么做 | 判定 |
|:---:|-----------|------|
| 1-1 | 打开**中国政府网政策文件库**（`www.gov.cn`）或对应部委官网 | — |
| 1-2 | 输入**文件全称**（带书名号内的完整名称）搜索 | 搜到 → 进第二步 |
| 1-3 | 搜不到时，改用**发文字号**搜（如 `国办发〔2026〕12号`） | 搜到 → 进第二步 |
| 1-4 | 两种都搜不到 | ⚠️ **大概率是名称或文号有误** → 退回作者确认，或改用缓冲表述 |

> **注意**：搜到"相似名字"的文件**不等于找对了**。公文名称差几个字常是两个不同文件，
> 必须**逐字比对全称**。

### 第二步：查状态（"这份文件现在还有效吗"）

| 动作 | 具体怎么做 | 判定 |
|:---:|-----------|------|
| 2-1 | 在原文页面找**施行日期**（不是印发日期） | 记下，与正文引用口径比对 |
| 2-2 | 搜「**废止 + 文件全称**」，看有没有废止通知 | 有 → ⚠️ **不可引用**，必须换文件 |
| 2-3 | 搜「**修订 + 文件全称**」，看有没有新版 | 有 → 改用**现行有效版本** |
| 2-4 | 对"十四五""三年行动"等**时段性政策**，确认是否仍在有效期 | 已过期 → 写"延续执行"或换依据 |

> **为什么这一步最容易漏**：文件真实存在但**已经废止**是最隐蔽的坑——
> 名称和文号都能搜到，只是搜到的那条是废止通知。

### 第三步：查对应（"引用的内容，原文真是这么说的吗"）

| 动作 | 具体怎么做 | 判定 |
|:---:|-----------|------|
| 3-1 | 打开原文，**Ctrl+F 搜正文引用的关键词** | — |
| 3-2 | **逐字比对**：正文概括的意思与原文是否一致 | 一致 → ✅ 通过 |
| 3-3 | 检查有没有**曲解或拔高**（原文说"鼓励"，正文写成"要求"） | 有 → ⚠️ 改回原文口径 |
| 3-4 | 检查**精确数字**（比例、期限、金额）与原文是否一致 | 不符 → ⚠️ 以原文为准 |
| 3-5 | 检查引用的是否为**本地区适用政策**（外省政策不可作本省依据） | 跨省 → ⚠️ 实质性错误，必须换 |

> **"鼓励"写成"要求"是最常见的一类**——原文是倡导性表述，正文写成了强制性义务。
> 这类错误审核时会被认定为**曲解政策**，比文号写错更严重。

### 三步核验记录表（照这个填，随稿交付）

```
# 政策引用核验记录

| # | 文件全称 | 文号 | 第一步存在 | 第二步状态 | 第三步对应 | 核验人 | 日期 |
|---|---------|------|:---:|:---:|:---:|:---:|:---:|
| 1 | 《××管理办法》 | 国办函〔2026〕12号 | ✅ | ✅ 现行有效 | ✅ 口径一致 | | |
| 2 | 《××工作条例》 | — | ⚠️ 未搜到 | — | — | | |

结论：1 处通过 / 1 处待作者确认（缺文号，无法核验）
```

### 与脚本的分工（重要）

| 谁来做 | 做什么 | 做不到什么 |
|-------|--------|-----------|
| `policy_cite.py` | 抽出全部引用、查格式、列成表 | 查不到文件是否存在 |
| **人工（本节三步）** | 查存在 / 查状态 / 查对应 | — |

**一句话**：脚本把"要核哪些"列清楚，**"核得对不对"必须人来做**。
两者是前后接力，不是互相替代。

## 五、查不到原文时怎么办：三种占位写法

**绝不编造**文件名称、发文字号、条款内容——这是公文写作的**红线**，没有例外。

| 占位写法 | 适用场景 | 示例 |
|---------|---------|------|
| **缓冲表述** | 方向上知道要引什么，但具体文件未定 | 「根据国家和本市关于人才引进的有关要求……」 |
| **待补标注** | 已确定要引某文件，但文号/日期未查到 | 「根据《××管理办法》（**〔待补：发文字号、发布日期〕**）……」 |
| **待核标注** | 记得有这份文件，但表述拿不准 | 「根据《×××》（**待核：文件全称与现行版本**）的部署……」 |

> **使用顺序**：优先用**缓冲表述**（不打断行文，审核也过得去）；
> 只有在"这份文件是论证的关键支撑、必须点名"时，才用待补/待核标注，
> 并在交付时**单独给出待补清单**。

## 六、交付时的溯源清单

引用超过 3 处、或涉及重要依据时，交付稿子同时附一份**政策引用溯源表**：

```
# 政策引用溯源表

| # | 位置 | 文件名称 | 发文字号 | 日期 | 状态 | 核对 |
|---|------|---------|---------|------|------|:---:|
| 1 | 第 7 行 | 《××管理办法》 | 国办函〔2026〕12号 | 2026年1月15日 | 要素齐全 | ☐ |
| 2 | 第 11 行 | 《××工作条例》 | — | — | 缺文号 | ☐ |

必须处理 1 项 / 建议处理 0 项
```

**生成方式**（自动，无需手写）：

```bash
python scripts/policy_cite.py 报告.docx --save 报告-政策引用溯源表.md
```

脚本会做这些事：

1. 抽出全文所有 `《》` 引用及其邻近的发文字号、日期
2. 判定每一条是"要素齐全 / 缺文号 / 缺日期 / 文号格式不规范 / 带待补占位"
3. 检出书名号不成对、同一文件两种写法、文号年份异常
4. 输出可直接附在稿子后面的 Markdown 溯源表

**脚本不做的事**（必须人工完成）：

- 联网核验文件是否真实存在
- 核验是否已修订或废止
- 核验条款内容与引用是否对应

## 七、与 E11 的衔接

SKILL.md **E11「政策文件不存在或未收录」** 给出的是**行为规则**（不编造 → 缓冲占位 → 给待补清单）；
本文件给出的是**操作规范**（格式怎么写、去哪个源核对、时效怎么验）。

| 情形 | 依据 |
|------|------|
| 用户要求引用某文件，但原文无法确认 | E11 |
| 引用格式对不对、文号括不括号、要不要补日期 | 本文件第二、四节 |
| 一次要核对十几处引用，怕漏 | 跑 `policy_cite.py` 生成溯源表 |
| 已废止/被修订的文件怎么处理 | 本文件第四节 |
| 商业来源能不能当依据 | 本文件第三节 |

## 八、质量评分侧

`scripts/quality_score.py` 会检查：

- 疑似编造政策（有书名号但**既无发文字号又无缓冲表述**）→ 扣 2 分
- 详见 `references/quality-scoring.md` §5.4

**处理优先级**：疑似编造属 **P0 红线**，无论总分多少都必须修复。
