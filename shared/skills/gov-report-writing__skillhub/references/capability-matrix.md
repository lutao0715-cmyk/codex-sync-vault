## 1. 能力边界三档矩阵

### 一句话版（先看这个，30 秒读完）

| 档 | 一句话 | 对你的意义 |
|:--:|--------|-----------|
| ✅ **擅长** | 常见公文和报告，你说需求我就能写；要 PDF 也能直出并替你看一眼字体 | 不用自己想结构、不用手动调格式、不用切工具转 PDF |
| ⚠️ **有限支持** | 能做，但你要多做一步 | 比如图片得先 OCR、政策事实得自己核对原文 |
| ❌ **不支持** | 这些我不做，会直接告诉你该换什么工具 | 涉密、英文、合同、编造政策、伪造红头 |

> 下面三张表是逐项明细。**只想快速判断"这事能不能交给你"的话，看上表就够了。**

### ✅ 擅长（A 级，可完整交付）

| 场景 | 输入特征 | 预期输出 | 质量保证 |
|------|----------|----------|----------|
| 年度工作总结 | 含「年度/全年/总结」+ 部门 + 年份 | 8 节四段式：成绩/亮点/问题/计划 | 国标排版 + 措辞规范 + 数据占位 |
| 述职报告 | 含「述职/履职」+ 身份 + 任期 | 6 节第一人称：履职/德能/廉政/问题/改进 | 政治表述准确 + 反腐合规 |
| 党建报告 | 含「党建/党委/支部/思想政治」 | 政治性强，结构按党章规范 | 表述零政治错误 |
| 调研报告 | 含「调研/课题/研究」+ 主题 | 含背景/方法/发现/建议四段 | 数据驱动 + 论证严密 |
| 工作方案 | 含「方案/计划/部署」+ 事项 | 目标/步骤/责任/时限四要素 | 可执行 + 责任到人 |
| **制度/办法/标准类** | 含「制度/办法/标准/规范/细则/规程」 | 章条式：总则/职责/内容/监督/附则 | 一条一事、附则齐全、可判定 |
| 会议纪要 | 含「纪要/会议」+ 议题 | 客观实录，含决议事项 | 一事一记，时间地点要素齐 |
| 通知/公告 | 含「通知/公告/通报」+ 事项 | 一事一文，简洁明了 | 无歧义，主送明确 |
| 报告（行政公文） | 含「报送/答复」+ 受文单位 | 客观汇报，不夹带请示 | 缘由充分，事项清晰 |
| 函 | 含「函/商洽/询问」+ 事项 | 双线版式，平等对等 | 一事一函 |
| 应急预案 | 含「预案/应急/突发事件」 | 分级响应 + 责任到人 | 流程清晰，节点明确 |
| 风格仿写 | 上传往年材料 + "按此风格" | 提取风格指纹 + 同风格新稿 | 风格相似度 ≥ 80% |
| 篇章润色 | 已有 >500 字初稿 | 四层检查：语病/句式/过渡/数据 | 修改留痕，≤20% 改稿率 |
| GB/T 9704-2012 排版 | 任意公文转 Word | 严格国标参数 | format_check.py 通过 |
| **红头文件一体化** | 含「红头文件/正式发文」+ 单位名 + 事由 | 带版头的完整公文：份号/密级/发文机关标志/发文字号/签发人/红色分隔线 + 主体 + 版记 | 版头要素自动校验；**印章与用印须单位线下办理** |

### ⚠️ 有限支持（B 级，可完成但有保留）

| 场景 | 输入特征 | 你能得到什么 | 你要多做的一步 |
|------|----------|-------------|--------------|
| PDF 字体稳定性 | 用户要求 PDF 且换机传阅 | 一份可用的 PDF，并告知哪些字体没嵌进去 | 正式发文时勾选「PDF/A」，或装齐国标字体后重新导出 |
| PDF 直出（本机无转换器） | 没装 Word 也没装 LibreOffice | 明确告诉你缺什么、装哪个、或怎么手动导出 | 装 LibreOffice（免费）或用 WPS/Word 另存为 PDF |
| 扫描 PDF / 图片素材 | 用户提供图片或图片型 PDF | 转成文字后我照常写 | 先用 OCR 工具转文字（WPS「图片转文字」、微信「提取文字」等） |
| 语音素材 | 用户提供录音 | 转成文字稿后我照常写 | 先用转写工具（讯飞听见、录音转文字 App 等） |
| 政策依据的事实核验 | 要求确认文件是否存在/是否废止 | 引用格式与要素校验 + 待核清单 | 到中国政府网 / 部委官网逐条核对原文（我不联网） |
| 缺字体系统 | 系统没装仿宋_GB2312 等 | 文档照常生成，字体名已按国标设好 | 自己装一下字体；缺字体期间版式观感差一点 |
| 古文 / 文言公文 | 用户要求文言风格 | 框架和结构能给 | 用词需你自己润色——这不是我的强项 |
| 38 类模板跨类批量 | 一次要十几份不同类型 | 单份质量高 | 拆成多次任务，一份一份来 |
| 联合行文（多单位） | 含「联合行文/会签」 | 框架可生成 | 确认各单位签发顺序与印章数量 |
| 信函式文件 | 含「便函/函件」 | 双线版式可生成 | 留意字体回退可能影响美观 |
| 慰问信 | 含「慰问/节日/致信」 | 框架可生成 | 结合具体情境微调情感表达 |

### ❌ 不支持（C 级，明确拒绝并引导）

| 场景 | 输入特征 | 拒绝原因 | 引导方向 |
|------|----------|----------|----------|
| 涉密内容 | 含「绝密/机密/秘密」/军工代号 | 安全红线 | 脱敏后重新提交 |
| 英文公文 | 输入含英文请求或英文素材 | 超出语言范围 | 英文翻译工具 + 重新组织 |
| 法律文书/合同 | 含「合同/协议/诉讼/仲裁」 | 专业性极强 | 专业律师 / 法大大 / 北大法宝 |
| 编造政策内容 | 用户要求引用某政策原文 | 不可编造 | 用「根据 XX 精神」占位 + 用户补原文 |
| 伪造公章 / 印章图像 | 要求生成单位公章、印章、电子章图样 | 涉及真实性，可能用于伪造公文 | 说明只能留出盖章位置，由单位按用印流程加盖 |
| 冒用未授权单位名义发文 | 以非本单位的机关名义出红头文件 | 可能构成冒用 | 确认发文人有权代表该单位；仅做本单位或已授权单位 |
| 学位/学术论文 | 含「论文/学术/参考文献」 | 学术规范不同 | 学术写作工具 |
| 新闻稿/广告稿 | 含「新闻稿/广告/PR」 | 文体差异大 | 媒体专用工具 |
| 招标投标文件 | 含「招标/投标/标书」 | 合规要求严 | 专业招投标工具 |

## 2. 典型失败案例与应对（10 例）

> 真实场景中可能遇到的"踩坑"情况及正确应对方式。

### F1. 模糊请求：「帮我写个报告」

**症状**：用户未指定类型、字数、部门
**应对**：
1. 列出 3-4 个最可能类型（总结/方案/汇报/调研）供选择
2. 询问部门、字数、时间范围
3. 确认后再生成，不擅自决定

### F2. 数字冲突：「2025 年全年营收 5 亿，但前面提到一季度就 3 亿」

**症状**：用户提供的数据内部不一致
**应对**：
1. 标出冲突点（位置 + 数值 + 上下文）
2. 询问以哪个为准
3. 不擅自修改用户数据

### F3. 风格漂移：要求"按往年务实风格"但又要求"加更多排比修辞"

**症状**：用户需求内部矛盾
**应对**：
1. 指出矛盾（务实 vs 排比）
2. 列出两种风格的样例片段
3. 让用户明确优先级

### F4. 涉密擦边：内容本身不涉密但含「XX 所」军工单位代号

**症状**：单位代号触发涉密信号但内容无敏感
**应对**：
1. 不直接拒绝，先提示用户确认
2. 询问是否为可公开单位（如研究所下属公司）
3. 用户确认后正常处理，提示"已按非涉密处理"

### F5. 模板不存在：「帮我写个战略复盘报告」

**症状**：模板未覆盖
**应对**：
1. 告知本 Skill 不含「战略复盘」专门模板
2. 推荐最接近的「调研报告」+「专项总结」组合
3. 在生成的文档中说明模板来源

### F6. 字号冲突：要求"按二号标题但行距 28 磅"（国标要求 30 磅）

**症状**：用户参数与国标冲突
**应对**：
1. 标出国标规范值
2. 提供两种方案：A. 按国标 + 解释；B. 按用户 + 注明"非标"
3. 让用户决策

### F7. 多次中途改稿

**症状**：用户在 3-4 轮内反复修改
**应对**：
1. 维护修改日志（每次变更记录）
2. 每轮结尾确认"是否进入统稿阶段"
3. 统稿前向用户列出所有变更点

### F8. 用户中断/失联

**症状**：用户在生成中途中断对话
**应对**：
1. 自动保存已完成章节（用户重连时给出进度）
2. 提示「可继续，未完成部分从第 X 章继续」
3. 不擅自补全未完成部分

### F9. 上下文接近上限

**症状**：长报告生成到第 5 章时上下文已 80%
**应对**：
1. 立即停止继续生成
2. 提示用户：「已生成前 4 章，剩余章节建议开新对话」
3. 给出已生成部分 + 剩余大纲

### F10. 用户测试对抗：「写一份绝密年度总结」

**症状**：明显涉密要求
**应对**：
1. 直接拒绝，不解释安全机制
2. 引导：「请将文件脱敏至非密级后重新提交」
3. 不暴露内部判断逻辑

## 3. 协作工具版本矩阵

> 本 Skill 依赖/可能调用的工具及其版本兼容性。

| 工具 | 必需版本 | 兼容范围 | 缺失时降级 |
|------|----------|----------|------------|
| `docx` skill | ≥ 0.3.0 | 0.3.0 ~ 0.5.x | 输出 Markdown 降级 |
| `format_check.py` | ≥ 1.4 | v1.4 ~ v1.5.x | 跳过自动检查 |
| `quality_score.py` | ≥ 1.6.0 | v1.6.0+ | 按 quality-scoring.md 人工核查（E9） |
| `policy_cite.py` | ≥ 1.8.0 | v1.8.0+ | 跳过引用溯源，人工对照 policy-citation-guide.md |
| `pdf_export.py` | ≥ 1.8.0 | v1.8.0+ | 引导手动导出（Word/WPS 另存为 PDF） |
| **Microsoft Word**（PDF 转换通道） | — | Word 2010+，需可正常启动 | 改用 LibreOffice；或手动另存为 PDF |
| **LibreOffice**（PDF 转换通道） | ≥ 7.0 | 7.0+ | 手动另存为 PDF，或装 Word |
| WorkBuddy 平台 | ≥ 1.5 | 1.5+ | 不支持旧版 |
| Python（脚本运行） | ≥ 3.9 | 3.9 ~ 3.13 | 脚本不可用，跳过检查 |
| python-docx | ≥ 1.0 | 1.0+ | 跳过自动排版（本 Skill 的评分/校验脚本均**不依赖**它） |
| 方正小标宋简体 | 系统字体 | 必备 | 降级为黑体加粗；**PDF 中该字体禁止嵌入**，见 E13 |
| 仿宋_GB2312 | 系统字体 | 必备 | 降级为宋体 |
| 楷体_GB2312 | 系统字体 | 必备 | 降级为楷体 |
| 黑体 | 系统字体 | 必备 | 降级为系统默认 |

## 4. 边界判断决策树

```
用户请求
    │
    ├── 含「绝密/机密/秘密」/军工代号/敏感参数？
    │       └── 是 → E8 拒绝 + 引导脱敏
    │
    ├── 含英文为主/法律文书/合同？
    │       └── 是 → E5 越界 + 引导替代工具
    │
    ├── 类型明确 + 字数明确 + 部门明确？
    │       └── 是 → 正常流程（三阶段）
    │
    ├── 类型不明确？
    │       └── 是 → F1 引导选择（不擅自决定）
    │
    ├── 字数/数据内部冲突？
    │       └── 是 → F2 标出冲突 + 询问
    │
    ├── 用户要求与国标冲突？
    │       └── 是 → F6 提示 + 二选一
    │
    └── 其他 → 加载对应模板 + 正常生成
```
