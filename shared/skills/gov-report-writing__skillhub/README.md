## 简介

`gov-report-writing`（中文名：公文写作）是一个专为国央企和党政机关公文写作场景设计的 WorkBuddy Skill。它内置了 GB/T 9704-2012 国标公文格式规范（含企业级扩展）、34 种模板框架（8 类工作模板 + 7 种行政公文 + 10 种专题模板 + 信函式文件 + 应急预案/议程/慰问信/专项总结/联合行文/转发性公文/请示批复联动/制度办法标准）、公文专用措辞词汇库，以及**五维 100 分质量评分**（合规/完整/规范/准确/文风），能够将一份标准公文从"调格式 + 写内容 + 润色 + 质检"的 2 小时工作压缩到几分钟。

## 核心功能

| 功能 | 说明 |
|------|------|
| 📐 国标排版 | 严格遵循 GB/T 9704-2012，自动设置页边距、字体、字号、行距、层级标题格式 |
| 📋 34 种模板 | 8类工作模板 + 7种行政公文 + 10种专题模板 + 信函式文件 + 应急预案/议程/慰问信/专项总结/联合行文/转发性公文/请示批复联动/制度办法标准 |
| ✍️ 公文用语 | 内置政治术语校验、口语→公文替换规则、常用句式库、**公文高频搭配不当 57 项检查清单** |
| 📊 质量评分 | 五维 100 分自动评分（合规30/完整25/规范20/准确15/文风10），输出问题清单与改进建议 |
| 🔎 政策引用溯源 | 抽出全文政策引用，校验发文字号/日期/括号格式，输出可附稿交付的**政策引用溯源表**；并附**人工核验三步清单** |
| 📄 PDF 一键直出 | 自动调用本机 Word / LibreOffice 转换，并**实测校验页数与字体嵌入状态**（决定发出去会不会跑版） |
| 🧭 渐进式加载 | **不必通读文档**——按「什么时候读哪个文件」表按需加载，只看到你需要的那一层 |
| 🛠 脚本参数速查 | 脚本报错时**告诉你改哪里**——格式类改文档、类型类加参数、环境类换途径，一张表说清 |
| 🚑 故障恢复三式 | 换路径 / 无缝续写 / 只重做受影响步骤，**优先自己试再问用户** |
| 🔒 安全红线 | 执行前自动识别敏感信号，占位符机制保护敏感信息 |

## 安全特性

- 执行前自动检测涉密信号（密级标注、项目代号、技术参数）
- 敏感信息自动用 `XX` 占位，防止泄露
- 全程本地处理，不上传云端
- 每份输出文档附带安全提示

## 技术要求

- **平台**：WorkBuddy / CodeBuddy (Cursor/Windsurf/Claude Code 兼容)
- **字体**（国标排版需要）：
  - 方正小标宋简体
  - 仿宋_GB2312
  - 楷体_GB2312
  - 黑体
  > 如系统缺少以上字体，Skill 会正常设置字体名并提醒用户安装；缺失期间自动降级（正文宋体 / 标题黑体加粗）。字体获取途径（WPS 自带 / 单位字体包 / 方正官网）与分系统安装方法见 [`references/troubleshooting.md`](references/troubleshooting.md) §1.4。运行 `python scripts/preflight_check.py` 可一键检测四槽位状态。字体属版权文件，不随 Skill 包分发。

## 能力边界说明

一句话说清楚：**常见的公文和报告，你说需求我就能写；少数场景要多做一步；还有几类我不做。**

**详细的边界矩阵、失败案例库与协作工具版本清单见 [`references/capability-matrix.md`](references/capability-matrix.md)**。

### ✅ 擅长（直接说需求就行）

| 你能要什么 | 这对你意味着 |
|-----------|------------|
| 38 类公文的框架 + 内容 + 措辞 + 排版（8 类工作 + 7 类行政 + 10 类专题 + 信函/应急预案/议程/慰问信/专项总结/联合行文/转发性公文/请示批复联动/制度办法标准/通报/公示/感谢信贺信/会议方案） | 不用自己想结构，也不用手动调格式 |
| **红头文件一体化生成**（版头要素确认 → 编排 → 置入 Word → 自检 6 项） | 说出单位名和事由，就能出一份带版头的正式公文 |
| 按 GB/T 9704-2012 国标排版（页边距/字体/行距/层级序号） | 交上去的版式是"标准长相"，不会被挑格式 |
| 照往年材料仿写新稿 | 上传旧稿说一句"按这个风格写"就行 |
| 已有初稿的润色打磨 | 语病、句式、过渡、数据一致性四层检查，含 5 类高频搭配不当专查 |
| **转成 PDF** | 自动调用你本机的 Word 或 LibreOffice 转换，并**校验页数与字体嵌入**——发出去会不会跑版，我先替你看一眼 |
| **核政策引用** | 抽出全文引用，列出"缺文号 / 缺日期 / 括号不规范 / 带待补标记"，生成一份可直接附稿的溯源表 |

### ⚠️ 有限支持（能做，但你要多做一步）

| 你想要 | 实际情况 | 你需要做什么 |
|--------|---------|------------|
| PDF 里标题字体的稳定性 | 方正小标宋简体授权属性为"禁止嵌入"，PDF 不会内嵌该字体 | 正式发文时用 Word/WPS 另存为 PDF 并勾选「符合 PDF/A」，或装齐字体后重新导出；只在单位内部流转可忽略 |
| 拿图片 / 扫描件 / 录音当素材 | 这些我读不了 | 先用 OCR 或转写工具变成文字，再发我 |
| 一次生成十几份 | 同时做会互相干扰 | 分开说，我一份一份出 |
| 特殊字体正确显示 | 我只能设字体名，装不了字体 | 自己装一下（见常见问题 Q4） |
| 政策依据的**事实核验** | 我不联网，无法确认文件是否存在、是否已废止 | 按溯源表逐条到中国政府网 / 部委官网核对原文（见 [政策引用指南](references/policy-citation-guide.md) §四·补「人工核验三步」） |
| **两个文种拿不准选哪个** | 我能给建议，但单位关系、会议程序要靠你判断 | 先查 [文种易混辨析](references/report-templates.md) §36 五组对照表 |

### ❌ 不支持（这些别找我）

| 你的要求 | 我会怎么反应 | 你该去哪 |
|---------|------------|---------|
| 涉密内容（密级标注、项目代号、未公开参数） | 直接拒绝，请你脱敏后重来 | 脱敏后再交给我 |
| 英文公文 | 明确告诉你不在我的范围内 | 英文写作工具 |
| 法律文书 / 合同起草 | 明确告诉你不在我的范围内 | 专业法律工具或律师 |
| 编造政策名称、发文字号、条款 | 我不编，宁可用「XX」占位让你补 | 单位 OA / 政府官网取原文 |
| 伪造红头 / 公章 | 涉及真实性，不做 | 用单位正式模板 |

### 素材与输入

**Q: 可以上传图片或扫描件吗？**
A: 不能直接读。本 Skill 的输入是**文字**，图片和扫描版 PDF（图片型）需要先用 OCR 工具转成文字，再把文字发给我。可用途径：平台已装的 OCR 类 Skill、WPS / Office 的「图片转文字」、微信 / QQ 的「提取文字」、或本机的 `tesseract`。**文字版 PDF**（能复制出字的那种）可以直接读。

**Q: 会议录音能直接整理成纪要吗？**
A: 录音本身不能直接处理，需先用语音转写工具（如讯飞听见、录音转文字类 App、平台内置的转写 Skill）转成文字稿，再把转写稿发给我。交给我时说明一句「这是会议录音转写稿」，我会先做口语→公文的替换再套纪要模板，比直接拿转写稿当正文干净很多。

**Q: 支持 PDF 输出吗？**
A: 支持直出。生成 Word 后说一句「转成 PDF」，Skill 会跑 `python scripts/pdf_export.py <docx路径>`，自动调用你本机的 **Microsoft Word**（优先）或 **LibreOffice** 转换，全程本地、不上传。转换后会**实测校验页数与字体嵌入状态**——这两项决定"发到别人电脑上会不会跑版"。想先看本机有没有可用的转换通道，跑 `python scripts/pdf_export.py --check`。

> **关于字体嵌入**：方正小标宋简体的厂商授权属性为 `fsType=2`（禁止嵌入），Word 导出 PDF 时不会内嵌该字体，因此**发到没装该字体的电脑 / 手机 / 微信里，标题可能被替换**（本机打开正常）。正式发文场景建议用 Word/WPS「另存为 PDF」并勾选**「符合 PDF/A」**，部分阅读器会以位图保留字形外观；或装齐四个国标字体后重新导出。仅在本单位内部流转，风险可忽略。

**Q: 生成的文档字体不对？**
A: 先跑 `python scripts/preflight_check.py` 查看四个国标字体槽位的检测结果。缺失时按推荐顺序获取：方正小标宋简体 / 仿宋_GB2312 / 楷体_GB2312 优先从 WPS Office（安装后自带）或单位内网字体包获取；Windows 自带的「仿宋」「楷体」（非 GB2312 版）可临时替代，格式检查脚本认可。安装时 Windows 10+ 可右键字体文件选「为当前用户安装」（免管理员），装完重启 Word / WPS 生效。缺字体期间文档仍可正常生成（自动降级为正文宋体 / 标题黑体加粗）。


### 能力与触发

**Q: 怎么触发这个 Skill？**
A: 在 WorkBuddy 中直接说需求即可自动触发，如"帮我写一份年度工作总结""按公文格式写个请示"。也可以说"用公文写作技能写……"显式指定。

**Q: 能处理 5000 字以上的长报告吗？**
A: 可以。超过 5000 字会自动启动分段生成策略：先生成大纲→逐章写作→每章确认→全文统稿，保证长文质量和上下文一致性。

**Q: 有没有参考范文？**
A: 有。`references/case-examples.md` 收录了 HR/财务/党建/安全/科研五条线的范文片段和专业点评，生成前可参考。

**Q: 想按往年材料的风格写怎么办？**
A: 上传一份往年材料，说明"按这个风格写"，Skill 会提取标题风格、用词偏好、语气基调等特征后按同风格生成新稿。

**Q: 能生成转发上级文件的通知吗？**
A: 可以，覆盖转发 / 批转 / 印发三类。Skill 会按被转发文件的来源自动选动词（上级→转发、下级→批转、本级→印发），并处理标题书名号嵌套（内层降为单书名号）、正文引据（完整引用被转发文件名称与发文字号）、被转发文件另页起排统一编页等规则。说「帮我写份转发上级 XX 文件的通知」即可。

**Q: 请示和批复能一起生成吗？**
A: 可以，支持成对生成。给出事项后，Skill 先出请示稿，再据请示生成批复稿，两稿的标题事由、批复引据的文号、主送与发文机关（双向互换）、日期先后自动对应，并做四项联动校验。批复表态分同意 / 原则同意 / 不同意三档，且表态前置。

**Q: 想定一个管理办法 / 制度 / 标准，怎么写？**
A: 说一句就行，比如「定一个《员工考勤管理办法》」。Skill 会按**章条式体例**（总则 → 职责分工 → 管理内容 → 监督考核 → 附则）出稿，并遵守几条制度专有规则：条文"一条一事"、通篇连续编号（章断条连）、附则必含解释机关 + 施行日期 + 与旧规定的衔接、制度正文不写主送机关也不盖章（这两项由随附的发布通知承担）。质量评分里「制度标准」是独立类型，自动豁免主送与印章两项要素。另外提醒一句：**"办法"和"方案"不是一回事**——一次性工作用"方案"，长期规则用"办法"。


### 质量与检查

**Q: 怎么给写好的公文打分？**
A: 运行 `python scripts/quality_score.py <文件路径>`，会按五维 100 分制（合规 30 / 完整 25 / 规范 20 / 准确 15 / 文风 10）评分，并输出问题清单和改进建议。支持 .docx / .md / .txt；用 `--type <类型>` 指定报告类型可提高章节校验准确度；草稿用 `--draft` 跳过占位符检查；程序化调用用 `--json`。90 分以上为 A 档可直接提交。评分标准详见 `references/quality-scoring.md`。

**Q: 质量评分和格式检查脚本有什么区别？**
A: 两者检查的层面不同，建议串联执行：`format_check.py` 管 **DOCX 排版层**（页边距、字体、行距、缩进、页码）；`quality_score.py` 管 **文本内容层**（政治术语、信息充分性、数据一致性、AI 痕迹等）。前者保证"长得像公文"，后者保证"内容够格"。

**Q: 格式检查脚本怎么用？**
A: 生成 Word 后可运行 `python scripts/format_check.py <文件路径>` 自动检查页边距/字体/行距/层级序号，支持 `--json` 和 `--quiet` 参数。

**Q: 稿子里的政策引用怎么核对？**
A: 跑 `python scripts/policy_cite.py <文件路径> --save 报告-政策引用溯源表.md`。脚本会抽出全文所有 `《》` 引用，逐个检查：有没有发文字号、有没有日期、括号是不是规范的六角括号 `〔〕`、有没有留「待补」标记，另外还会查书名号是否成对、同一份文件有没有两种写法。输出的**政策引用溯源表**可以直接附在稿子后面，审核时"照着清单查"而不是"凭着感觉翻"。

> **注意**：这个脚本是**规范与要素完整性校验，不联网、不做事实核验**。文件是否真实存在、是否已被修订或废止、条款内容对不对，必须按表里的来源优先级到**中国政府网 / 国务院政策文件库 → 部委官网 → 省级政府官网 → 人民日报新华社**核对原文。我不会替你判断真假，只帮你把该查的列清楚。
>
> **怎么核**：`references/policy-citation-guide.md` §四·补 提供了**人工核验三步清单**（查存在 → 查状态 → 查对应），每步给出具体动作与判定标准，并附一张可直接随稿交付的核验记录表。

**Q: 怎么确认这个 Skill 装完整了？**
A: 跑一次自检：`python scripts/preflight_check.py`。它会检查 Python 版本（3.9+）、SKILL.md / README.md 是否齐全、references **12 个**参考资料是否都在、scripts **5 个**脚本语法是否正常、报告类型识别表挂接是否完整、**国标字体四个槽位是否可用**，并给出逐项结果和修复建议。加 `--json` 可程序化读取结果，`--quiet` 只看问题项。


### 出错与边界

**Q: 能否处理涉密文件？**
A: 不能。本 Skill 内置安全检测机制，遇到涉密信号会自动拒绝处理。请将文档脱敏后再使用。

**Q: 生成时遇到错误或失败怎么办？**
A: 本 Skill 内置 13 类错误处理机制（E1-E13），覆盖字体缺失、文件损坏、上下文过长、生成失败、越界、并发、模糊请求、恶意输入、评分脚本不可用、涉密擦边误伤、政策文件不存在、占位符超限、**PDF 转换失败与字体嵌入**。失败时会自动重试 1-2 次，无法恢复则输出 Markdown 降级版本（PDF 转换失败除外——版式不对宁可不生成，会引导你手动导出）。**每类都告诉你「你会看到什么 / 你该做什么 / 为什么会这样」三行**，全部规则与"为什么会这样"的完整说明见 [`references/troubleshooting.md`](references/troubleshooting.md) 第二部分。

**Q: 怎么处理用户提的模糊需求？**
A: 例如"帮我写个报告"这种类型不明的请求，Skill 会先列出 3-4 个最可能类型供你选择，再询问部门、字数、时间范围，不会擅自决定关键要素。

**Q: 生成的公文 AI 味很重怎么办？**
A: 三步处理：① 跑 `quality_score.py`，文风度维度会标出 AI 痕迹命中项（破折号滥用、机械三段式、"值得注意的是"类套语、过度排比、空洞总结句）；② 对照 `references/ai-traces.md` 的 12 类模式逐段改；③ 补**具体数据、事例、责任分工、时间节点、量化成效**——AI 味的本质是内容空泛，补上这五样后"机器感"会自然消失。分数目标 90+（A 档）。
> **另外还有一遍"人味二审"**：痕迹消完不等于像人写的。`references/ai-traces.md` §四 给了**八类人味信号**（意义膨胀 / 假深度 / 规则三连 / 元叙述 / 均匀用力 / 无细节 / 书面腔 / 零意外）。其中"**零意外**"最好用——真稿总有几处具体到只有本单位才写得出的东西，通篇可替换就是模板填充。

**Q: 占位符（XX）太多，文档没法用怎么办？**
A: 这是刻意的保护机制——宁可留空也不编造。按密度分三档处理：低于 5% 属正常，交付时会列出占位清单方便你批量替换；5%~20% 会逐项列出待补信息；**超过 20% 说明素材严重不足**，此时我不会强行生成全文，而是先给框架 + 待补充信息清单，等你补全再生成。若你明确说「这是草稿」，则不受此限制。

**Q: 要引用的政策文件我找不到原文怎么办？**
A: 我不会编造政策名称、发文字号和条款内容（这是公文红线）。处理方式：① 先查 `references/policy-database.md`，常用文件已收录；② 未收录的用缓冲表述占位，如「根据 XX 关于 XX 的要求」，并给你一份待补清单（文件全称、发文字号、生效日期、需引用的具体条款）；③ 你从单位 OA 或政府官网拿到原文后补进去即可。注意：无发文字号且无缓冲表述的疑似编造引用，质量评分会扣 2 分。
