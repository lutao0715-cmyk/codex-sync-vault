# 去 AI 味（deai-humanize）

汇报类文档（复盘/周报/方案）在交给老板前过一遍。目标不是「改得花哨」，而是**让文字像人写的**：去掉机械的排比与金句、混用的引号、无意义的表情符号，同时一个数字都不能丢。

用户触发话术：`帮我去 ai 味`、`AI 味太重`、`润色成真人写的`。

## 1. 高频 AI 味清单（复盘文档实测命中）

| 类型 | 实测症状 | 改法 |
|-|-|-|
| 破折号 | 一篇里 30 处 `——`，用来代替逗号/冒号 | 降到 0；改 `，` 或 `：`。**这是最明显的机器味** |
| 引号混用 | ASCII `"` / 中文 `“”` / 直角 `「」` 三种并存 | 统一成中文 `“”`（大陆汇报文档惯例） |
| 表情符号 | 表格「评价」列全用 ✅ / ❌ | 换成文字（`好` / `差`），并列时删掉冗余列 |
| 夸大副词 | 全面超额、均超预期、显著、极重、极窄、绝对主力 | `全面超额`→`全部超额`；`全面低于`→`都低于`；`极重`→`很重` |
| 伪洞察 | `……互相印证`、`……完全验证`、`这印证了……` | 改成平铺事实：`运营周记和数据曲线能对上` |
| 自夸结论 | `说明我们的内容评估能力是可信的` | 换成业务判断：`分级本身是准的` |
| 金句结尾 | `流量加成“有意义，但有代价”`、`量质双超` | 拆成陈述：`流量加成有用，但有代价` |
| 否定式排比 | `靠的不只是曝光投放量，更靠……`、`没有带来“深度”和“关系”` | `靠的不是多给曝光，而是……`；去掉引号强调 |
| 标题词 | `核心判断：` | 换 `结论：` |
| 生硬书面语 | `需与……对照检验`、`以剥离人群差异`、`应成为……检查项` | `需要跟……对比`、`用来剥离人群差异`、`应该成为……检查项` |
| 自检口径 | `<p>次均曝光播放时长XQ</p>`（残留字符） | 逐单元格读一遍，抓残留字符 / 半角冒号 / 中英数字空格不统一 |

数字与口径备注**一个都不能改**；「仅作参照」「口径未标注」这类免责说明属于正式汇报的必要成分，保留。

## 2. 操作流程（飞书文档）

### 2.1 全量拉取（关键：别漏块类型）

```bash
lark-cli docs +fetch --doc <token> --doc-format xml --detail with-ids > doc.xml
```

**踩过的坑：** 只按 `h1|h2|h3|p|callout|table|img|grid` 过滤会**整章漏掉**内容 —— 正文可能挂在 `<ul><li>` 里（本项目漏了第五章 4 条 + 第一章 4 条效率要点，第一轮改写完全没碰到它们）。

```python
# 正确做法：把所有可能承载正文的块类型都枚举
for m in re.finditer(r"<(h1|h2|h3|p|li|callout|quote)\b([^>]*?)>(.*?)</\1>", c, re.S):
```

生成「块 id → 纯文本」清单后，再统一扫描 AI 味特征词，确认覆盖全了。

### 2.2 逐块改写：用 `block_replace`，不要用 `str_replace`

```bash
lark-cli docs +update --as user --doc <token> \
  --command block_replace --block-id <块id> --content '<p>新文本</p>'
```

- `str_replace` 匹配的是**单个文本 run**，一旦目标文字跨了 `<b>` 边界就静默匹配失败 → 一律用 `block_replace`。
- `block_replace` 只换内容，**保留块位置**（表格单元格、callout 子块、列表项都能改）。
- **块 id 会变**：改完再 fetch 时同一逻辑块换了 id，**不要复用旧 id**；本轮没改到的块必须重新 fetch 后再定位（本轮有 3 处因此漏改）。
- 保留原有强调：原块 if 以 `<b>` 开头且以 `</b>` 结尾 → 用 `<b>` 包住新文本；段落里**局部**加粗的要显式写回 `<b>…</b>`，否则强调会整段丢失。

### 2.3 用脚本批量驱动 + 双重校验

把改写清单写成 `{块id: 新XML}` / `{块id: [(旧串, 新串)]}` 两个 dict，脚本里：

1. 对块**纯文本**先做 substring 校验，打印 `[no match] <id>: <旧串>` —— 字符级不一致（半角/全角、空格）在这里就能暴露；
2. 顺序调用 CLI，**不要只信 `"ok": true`**：实测有块返回 ok 但内容未变。必须回读文档、逐块对比改写前后的纯文本，列出「存在且未变」的块作为漏改清单；
3. 剩下的漏改块重新 fetch 后跑第二轮。

## 3. 交付前核查

```python
# 1) AI 味清零
for k, p in {'破折号': '——', 'ASCII引号': '"', '直角引号': '[「」]',
             'emoji': '[\u2705\u274c]', '全面': '全面', '完全': '完全',
             '显著': '显著', '印证': '印证'}.items():
    print(k, len(re.findall(p, t)))

# 2) 数据完整性：把关键数字列成清单逐个 count，必须全部 > 0
# 3) 结构完整性：<img> 数量、<h1> 章节列表与改前一致
```

顺手修正的硬伤（改文时一起提给用户）：

- 标题写的条目数 ≠ 实际行数（`做得好的六件事` 实际 5 条）→ 改成实际数；
- 数字与名字对不上（`共 6 人` 只列了 5 个）→ 改成 `共 6 人，包括……` 并把疑点回报用户，**不要自己删数字**；
- 中英数字空格不统一（`34位`/`场均20000+`）→ 统一成 `34 位`、`场均 2 万+`。
