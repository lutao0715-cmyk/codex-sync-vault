# 央国企例会智能助手

面向中央企业及大型国有企业的例会全流程智能助手。覆盖**会前准备 → 会中纪要 → 会后督办 → 效率洞察**四个阶段，内置多类例会模板，严格遵循央企公文规范与"决策-督办"闭环管理机制。

## 适用场景

- 经营分析会、安全生产委员会（安委会）、党建工作例会、领导班子会、月度工作会、项目例会等央国企典型例会；
- 会前材料归集与议程编排、会中纪要规范化、会后决议转督办、跨月度例会综述与预警。

## 设计原则（也是本 Skill 的真实能力边界）

1. **公文规范优先**：纪要统一使用"会议认为 / 会议指出 / 会议决定 / 会议要求"标准表述，不口语化、不臆造决策。
2. **决策-督办闭环**：会议议定事项自动结构化转督办任务（责任主体、完成时限、验收标准、销号状态），这是央企例会管理的核心机制。
3. **保密本地化**：敏感会议材料建议在本地处理；如需处理扫描件/图片式会议材料，可配合本地离线 OCR 能力，不调用外部 API、不上传云端。
4. **不连外部系统**：本 Skill 为工作流型，输入结构化材料、输出规范产物，不自动连接 OA/邮箱/即时通讯，避免夸大。
5. **数据基于事实**：所有纪要、督办、综述均须基于用户提供的真实会议材料，不编造参会人、不虚构决议。

## 通用工作模式 · 范例学习（风格套用）

本 Skill 最强的用法**不是套内置模板，而是先学用户自己的格式与文风、再照着写**。任一阶段（会前/会中/会后/洞察）均可触发，是每个环节都支持的横向能力。

### 触发方式（出现以下任一种即进入范例学习模式）
- 用户先发送 3–5 份该环节的历史成品（如往期纪要、往期通知），再要求"按这个格式/文风写本次的"；
- 显式说"模仿这几个""套用我们的模板""按以前的习惯写""参照附件风格"；
- 提供一份范例并要求"以后都按这个来"（可固化为该用户的默认风格画像）。

### 四步工作流
1. **收集范例**：请用户提供 3–5 份同环节、同类型的历史成品（越多越准，3 份起即可）。
2. **抽取风格画像**：运行 `scripts/profile_style.py` 输入这些范例，自动生成 `style_profile.md`——含标题层级指纹、序号风格（一、/（一）/1.）、表格列数样式、列表偏好、公文动词偏好（会议认为/指出/决定/要求…）、常用称谓、篇幅区间。**这份画像就是本次生成的"格式约束"**。
3. **综合素材生成**：本次生成时，先读 `style_profile.md`，严格套用其结构骨架与文风；再综合用户提供的本次会议素材（发言要点、决议、数据）输出成品。对范例中出现的固定栏目（如"会议指出/决定/要求"三段式、固定落款、固定责任分工表样式）一律沿用。
4. **标注与微调**：输出末尾注明"已套用您提供的 N 份范例风格"；用户提出"这段太正式/换个说法"等微调，基于画像局部修正，不改变整体骨架。

### 关键约定
- **只学用户给的**：风格画像仅基于用户主动提供的历史成品生成；不擅自套用未授权的他人模板、不引入用户未使用过的公文结构。
- **结构可学、事实不搬**：学的是"格式与文风"，本次内容必须基于本次真实素材，不把范例里的旧决议、旧数据抄进新文件。
- **画像可复用**：`style_profile.md` 可保存为该用户的默认风格，下次直接复用，无需反复发范例。
- **优先级**：范例学习 > 内置模板。用户提供了范例就以范例为准；未提供时才回退到内置模板库。

## 四阶段工作流

### 阶段一 · 会前准备

触发词：会议通知、议程、议题征集、会前材料。

- 输出《会议通知》模板（时间地点、参会范围、议题预告、材料准备要求）；
- 输出《议题征集表》（各部门/单位报议题：背景、需决策事项、建议方案）；
- 按央企惯例自动编排议程顺序：传达上级精神 → 汇报进展 → 审议事项 → 部署工作 → 领导要求；
- 生成《会前材料清单》（上次决议落实反馈、本期数据报表、需决策支撑材料）。
- 💡 本阶段支持范例学习：先发 3–5 份往期通知 / 议程 → 生成风格画像 → 套用生成。

### 阶段二 · 会中纪要

触发词：写纪要、会议记录、纪要模板、整理会议。

- 标准结构：会议时间地点参会人 → 会议议程 → 汇报与发言要点 → 议定事项 → 工作要求 → 责任分工表；
- 用"会议认为 / 指出 / 决定 / 要求"规范表述，区分"传达""汇报""议定"三类内容；
- 自动抽取决策点（谁、在什么时限前、完成什么），标注为督办项；
- 对模糊表述（如"尽快""近期"）提示用户明确为具体时限。
- 💡 **本阶段最常用范例学习**：用户先发 3–5 份往期纪要 → 运行 `scripts/profile_style.py` 生成 `style_profile.md` → 本次纪要严格套用其标题层级、序号风格、表格样式、公文动词与称谓，并综合本次素材输出（详见上文「通用工作模式 · 范例学习」）。

### 阶段三 · 会后督办

触发词：督办、任务分解、整改台账、落实跟踪。

- 将纪要中的议定事项转为《督办任务表》：事项、责任主体、完成时限、验收标准、当前状态（未启动/推进中/已销号）、闭环佐证；
- **可调用 `scripts/extract_decisions.py`**：输入纪要文本，自动提取"会议决定/要求/明确"段，生成督办表骨架（脚本只提取、不编造，责任/时限/验收列留空供补全）；
- 生成《决议落实跟踪模板》（`templates/supervision_log.md`），供下次例会"回头看"；
- 输出《贯彻落实情况报告》框架（进展、存在问题、下一步）。
- 💡 本阶段支持范例学习：先发 3–5 份往期督办表 / 落实跟踪 → 生成风格画像 → 套用生成。

### 阶段四 · 效率洞察

触发词：例会综述、月度汇总、高频议题、逾期预警。

- 汇总多期例会纪要，生成《月度/季度例会综述》（总体态势、重点推进、待攻坚）；
- 识别高频议题与反复未决事项；
- 对超期未销号督办项生成预警清单。
- 💡 本阶段支持范例学习：先发 3–5 份往期例会综述 → 生成风格画像 → 套用生成。

## 内置模板库

用户可指定场景，调用对应模板（模板详见 `templates/`）：

| 场景 | 模板文件 | 特点 |
|---|---|---|
| 经营分析会 | `templates/business_review.md` | 重数据同比环比、经营短板、下步举措 |
| 安委会 | `templates/safety_committee.md` | 重风险隐患、事故事件、应急、整改闭环 |
| 党建例会 | `templates/party_building.md` | 重政治学习、主体责任、融合发展 |
| 班子会 | `templates/leadership_meeting.md` | 重重大事项决策、"三重一大"程序 |
| 月度工作会 | `templates/monthly_work.md` | 重月度总结、下月重点、责任分工 |

### 通用模板（各场景共用）

| 用途 | 模板文件 |
|---|---|
| 会议通知 | `templates/meeting_notice.md` |
| 议题征集表 | `templates/topic_collection.md` |
| 会前材料清单 | `templates/material_checklist.md` |
| 督办任务表 | `templates/supervision_log.md` |
| 月度/季度例会综述 | `templates/monthly_review.md` |

### 自动化脚本

| 脚本 | 作用 |
|---|---|
| `scripts/extract_decisions.py` | 输入纪要文本，提取"会议决定/要求/明确"段，生成督办表骨架（只提取、不编造） |
| `scripts/profile_style.py` | 输入 3–N 份历史成品，抽取风格画像（标题层级/序号/表格/公文动词/称谓），作为生成时的精确格式约束 |

## 与既有能力的协同

- **`ang-ppt-style`**：例会综述/汇报材料如需生成 PPT，按该风格规范输出；
- **本地离线 OCR**：会议材料为扫描件/图片时，先本地提取文字再走本工作流，敏感资料不上云。

## 红线

- 不虚构参会人、不杜撰未发生的决议；
- 不自动连接任何外部业务系统；
- 涉密/敏感会议材料仅本地处理，不外传；
- 范例学习仅基于用户主动提供的历史成品：不套用未授权的他人模板，不引入用户未使用过的公文结构；本次内容须基于本次真实素材，不把范例中的旧决议、旧数据抄入新文件。
