# 滑雪晨报 & 户外日报 · 可移植生成手册

> **版本** v1.0 ｜ **整理日期** 2026-10-12 ｜ **样本期** 2026-10-11（滑雪 27 条 / 户外 37 条，双份全达标）
> **用途**：把这套「搜新闻 → 校验 → 出两份 HTML 日报」的流程搬到任意 agent 工具（Claude Code / Codex / Cursor / 自建 agent）上，跑出同样效果。

## 0. 先明确你要交付什么

每次执行产出 **两份自包含 HTML**（单文件、内嵌 CSS、无外部依赖、手机可看，深色主题）：

| 产物 | 文件名 | 条数 | 版块 | 结构 |
|---|---|---|---|---|
| 滑雪晨报 | `ski-morning-daily.html` | **27** | **6** | 单列卡片流 + 顶部 stats-bar |
| 户外日报 | `outdoor-adventure-daily.html` | **37** | **7** | 3 列自适应网格 + 顶部 stats-bar |

两份都是**数据驱动生成**——不是手写 HTML。数据块写好 → 脚本渲染 → 校验脚本验收。**严禁让模型直接输出整份 HTML**（历史上多次被输出长度限制截断，产物残缺）。

## 2. 全流程总览（8 个阶段）

```
A 状态确认  →  B 选题搜索  →  C 配额分配  →  D 写数据块
                                                ↓
H 归档收尾  ←  G 验收  ←  F 去重校验  ←  E 生成 HTML
```

| 阶段 | 干什么 | 产物 | 卡点 |
|---|---|---|---|
| A | 确认今天日期、上期日期、是否已有当天产物 | 日期常量 | 别盲目覆盖 |
| B | 按搜索矩阵找新闻，每条凑齐「标题+正文+来源+标签」 | 候选池 | **时效 7 天** |
| C | 按版块配额 + 国内外配额 + 8 组配比做取舍 | 定稿清单 | 先解约束再写稿 |
| D | 写成 Python 字面量数据块 | `data_MMDD.py` | 引号/逗号铁律 |
| E | 补丁器改日期 + 换数据块 → 跑渲染 | 两份 HTML | 不要手写 HTML |
| F | 跑 `verify_dedup.py` | 校验报告 | 基线别用 `*_latest_titles.json` |
| G | 条数/版块/标签/编号/日期逐项 grep 验收 | 验收记录 | 全绿才算完 |
| H | 写日志、备份当期为下期基线、交付 | memory + `.bak` | **备份丢了 → 下期没基线** |

## 5. 阶段 B：选题搜索（决定内容质量的关键环节）

### 5.1 时效铁律

- **只收 7 天内的新闻**。超过 7 天的一律丢弃，除非它是"仍在持续发展的事件"，且正文要用进行时表述（"本周仍在…""预计 10 月中旬…"）。
- 每条必须有**明确时间锚点**（具体日期或"本周/本周末"），避免模糊表述。
- 未来日期只能来自**官方公告**（赛程、开板日、发布会日期）。⚠️ 数据源 `miraitalk.com` 直接拉黑——常编未来日期。

## 6. 阶段 C：配额分配（先解约束，再写内容）

**顺序不能颠倒**——先定约束，再倒推选题，才能一次成型不返工。

1. **固定义务**：条数（27／37）、版块数（6／7）、国内外配额。
2. **先安排"天然归属"明确的条目**：行业类几乎必属 `multi`；安全提示类自带 `water`/`fish` 属性；雪场开板类必属 `ski`。
3. **算余量表**：用 37 减去已定额，得出每个运动组还缺几条。
4. **把缺口当选题指令去搜**：缺 2 条 `air` → 就专门搜滑翔伞；缺 1 条 `fish` → 专门搜路亚。
5. **国内选题常年超额**：先列全部候选（曾出现单期 8 条候选、配额只有 3 条），再排序取舍。
   取舍口径：**优先有国际参与度或明确公共价值的**（国际公开赛、国字号赛事、执法/政策通报），纯地方性活动让位。

## 7. 阶段 D：写数据块（最容易炸的一步）

### 7.1 滑雪：`SECTIONS` 列表

```python
SECTIONS = '''[
{"name": "🔥 今日热点", "items": [
 {"t": "标题", "p": "正文", "tag": "intl", "src": "来源"},
 {"t": "标题", "p": "正文", "tag": "china", "src": "来源"}
]},
{"name": "⚔️ 竞技赛场", "items": [
 ...
]}
]'''
```

### 7.2 户外：`CARDS` 字典

```python
CARDS = {
"🔥 今日热点": [
 ["multi", "标题", "正文", "来源"],
 ["run",   "标题", "正文", "来源"]
],
"🥾 徒步越野": [
 ["hike",  "标题", "正文", "来源"]
]
}
# CARDS 必须放在 SPORT_GROUPS 之前 —— 校验脚本抓的是文件里第一个 '{'，
# 若 SPORT_GROUPS 排在前面会读到整数 → TypeError: 'int' object is not iterable
```

### 7.3 三条书写铁律

1. **引号铁律**：`t` / `p` 的值里**只能用中文「」**。出现 ASCII 双引号会与定界符冲突 → `SyntaxError`。
2. **逗号铁律**：每个列表项行末**必须有逗号**。漏了会报 `SyntaxError: unmatched '}'`，且**报错行号指向下一行的组收尾符**，排查极费时。
3. **标点风格**：正文统一用中文全角标点；数字与英文品牌名保留半角。

```bash
python3 -c "import ast,importlib.util as u;s=u.spec_from_file_location('d','data_1013.py');m=u.module_from_spec(s);s.loader.exec_module(m);d=ast.literal_eval(m.NEW_SECTIONS);print(len(d),sum(len(x['items']) for x in d))"
# 期望输出：6 27
```

## 8. 阶段 E：生成 HTML

### 8.1 滑雪（补丁式，推荐）

```bash
cp gen_ski.py gen_ski.py.bakMMDD          # ① 备份 —— 这个备份就是"上一期"的去重基线
python3 patch_template.py --date 2026年10月13日 --weekday 星期一 \
    --sections-file data_1013.py --footer "数据来源：PowderGuide / FIS 等 30+ 中外媒体"
python3 gen_ski.py
```

`patch_template.py` 只做三件事：改 3 个日期常量、整块替换 `SECTIONS`、改页脚来源。**它不碰 HTML 模板**——所以样式永远是稳定的。

### 8.2 户外（拼接式）

```bash
cp gen_outdoor.py gen_outdoor.py.bakMMDD
# 数据块 CARDS 写到 /tmp/cards_sepN.py，模板尾部从旧文件里切出来

cat /tmp/cards_sepN.py /tmp/tail_sepN.py > gen_outdoor.py

```

> CARDS 必须**内联**进 `gen_outdoor.py`，不能 `from cards_outdoor import CARDS`——校验脚本只读这一个文件。

## 9. 阶段 F：去重与校验（三条防线，缺一不可）

```bash
python3 verify_dedup.py ski --n 5        # 滑雪：基线上溯 5 期
python3 verify_dedup.py outdoor --n 3    # 户外：基线上溯 3 期
```

脚本自动完成：结构校验（条数／版块／标签／编号连续性／日期）+ 跨期 6 字 shingle 查重（过白名单）+ 同期内部查重。

### 9.1 基线规则（踩过大坑）

- ❌ `ski_latest_titles.json` 被生成器**每次覆盖**，绝不能当"上一期"用。
- ✅ 正确基线 = `patch_MMDD.py` ／ `gen_ski.py.bakMMDD` ／ `gen_outdoor.py.bakMMDD`。
- 脚本已内置「**剔除当天补丁**」逻辑——历史上两次出现"拿今天当昨天"，误报 27 条全重复。

### 9.2 白名单（假阳性放行）

6 字命中片段若为**纯品牌／年份／通用赛事名** → 放行：`XGames`、`202627`、`Atomic`、`Salomon`、`世界杯`、`FIS`、`BOA`、`UCI`…
若为**句式模板或具体事实** → **必须改题**。

### 9.3 句式模板黑名单（跨期复用必须换模板，不能只换地区/对象/品牌）

- 「开板日历 / 开门时间表」类
- 「X月X日或成北美超级开板日」类
- 「索尔登揭幕战」类
- 「启动史上最大XXX」类
- 「媒体名 + 年份 + 品类 + 测试」类 → 去媒体前缀 + 结论前置
- 「雪季进入最后 N 周/天」类 → 换主语视角
- 「X 换帅：人名＋日期＋接任」类 → 去掉「换帅」，人物关系前置
- 「X 定档 X月X日开幕/首映」类 → **「定档」二字默认禁用**（曾连续三期复发）
- 「X 第 N 季赛历 / 阵容敲定」类 → 上期报过就不能只换角度重发，必须换事件
- 「人名 + 冒号 + 结论」起手（户外）
- **低成本通则**：通用短语里**插一个「的」字**就能打断 6 字连续片段。

### 9.4 正文事实级重复（shingle 抓不到）

6 字检测**只管标题**。若上一期内容特别密集，必须把上期全部标题打印出来人工过一遍，再决定正文里哪些**具体数字、雪场名、日期**不能重复写。

### 9.5 易撞主题清单（跨期需换角度）

X Games 联赛、雪盟 Snow League/Cardrona、Aspen、惠斯勒、路易斯湖、日本开季日历/二世谷、Vail 董事会 Oasis 提名、BOA 雪靴、戈吉亚、曾坪；
**酒店/雪场品牌扩张类**：Bear Den、Canopy by Hilton —— 同一品牌 10 天内极易二次撞题。

## 12. 已知坑速查表

| 症状 | 原因 | 解法 |
|---|---|---|
| `SyntaxError: unterminated string literal` | 数据块里用了 ASCII 双引号 | 全改中文「」 |
| `SyntaxError: unmatched '}'`，行号指向下一组收尾 | 列表项漏逗号 | 每项行末补逗号 |
| `TypeError: 'int' object is not iterable` | `gen_outdoor.py` 里 `SPORT_GROUPS` 排在 `CARDS` 之前，校验器抓到整数 | 把 `CARDS` 挪到最前 |
| 配比报告正常但条数少 1 | 卡片 tag 写了 `SPORT_GROUPS` 里不存在的键（如"水上"） | 只能写 `water`；水上运动的合法键是 自由潜/潜水/冲浪/帆船/皮划艇/游泳/桨板 |
| 校验报"27 条全重复" | 把今天的补丁当成了昨天的基线 | 用 `--n` 指定期数，脚本会剔除当天；确认文件名日期 |
| 校验器报错日期对不上 | 正则写死了月份 | 日期正则用 `2026年(?:9|10)月` |
| HTML 生成成功但内容残缺 | 让模型直接手写整份 HTML 被截断 | 一律走"数据块 + 渲染器" |
| 户外条数 38 不是 37 | 配比调平后忘了改总数 | 改完跑 `gen_outdoor.py` 看统计 |

## 13. 迁移到新机器 / 新 agent 工具：6 步清单

1. **复制 `scripts/` 三个脚本**到新工作目录（这三个决定产出质量，必须原样搬）。
2. **改路径引用**：脚本里没有硬编码路径，但 `verify_dedup.py` 以**脚本自身所在目录**为工作目录（`pathlib.Path(__file__).parent`）——所以脚本必须和数据、产物放同一目录。
3. **确认 Python 环境**：需要 3.8+，只用标准库（`re`/`json`/`ast`/`pathlib`/`itertools`/`argparse`/`collections`），**零第三方依赖**。
4. **给新 agent 装提示词**：把 `PROMPT.md` 里的「工作流提示词」作为系统提示或技能定义；把「单次执行提示词」作为用户指令。
5. **第一期满跑**：先按 5.5 的四要素建立候选池 → 走 C/D/E/F/G，确认 `verify_dedup.py` 三项全绿。
6. **建立基线习惯**：每期结束保留 `patch_MMDD.py` + `gen_*.py.bakMMDD`，否则跨期查重形同虚设。

### 效果一致性的关键判断点

| 维度 | 一致性来源 | 换工具会不会变 |
|---|---|---|
| HTML 版式 | 内嵌在 `gen_*.py` 模板里 | **不会**（脚本不变） |
| 条数/版块/标签 | 校验脚本硬校验 | **不会**（脚本不变） |
| 去重严格度 | `verify_dedup.py` 算法 | **不会**（脚本不变） |
| 选题质量 | 模型搜索能力 + 搜索矩阵 | **会**——取决于新工具的联网搜索质量 |
| 文案质量 | 模型写作能力 + 句式黑名单 | **会**——黑名单必须完整带过去 |
| 时效把控 | 靠提示词里的「7 天铁律」 | **会**——这条最容易在新工具上失守 |

> 结论：**版式与规格是脚本保证的（100% 可复现），内容质量是提示词 + 搜索能力保证的（需要在新工具上跑一期校准）。**
