何时读本文件：首次 build、任何 build 重跑、独立 QC/framecheck 或准备交付前；响度异常、渲染降级和抽帧复核也读本文。

## 4. QC 质检单解读

`svf build` 成功时 stdout 输出单张 JSON 质检单:`stages`(各环节 cached/ran)、`artifact`(成片/封面路径与时长)、`audio`(`loudness` 终检三值、`voice_baseline` 基线三值、bgm 状态)、`qc.blank_scan`、`qc.pixel_scan`、`qc.centroid_scan`、`qc.timeline_gate`、`qc.frame_check`。判定:

- `qc.blank_scan` 有空白时间点 → build 会直接退出 1 且不产出成片:查这些时间点对应场景,修复该帧后零参数重跑;
- `qc.pixel_scan.violations` 非空 → build 输出质检单后退出 1:墨迹越界(类别 `x<160`/`x>920`/`y<180`/`y>1560` + bbox;**bbox 为对象 `{x0, x1, y0, y1}`,字段名即语义**),按红线修帧后零参数重跑(tts cached 不计费);
  - `qc.pixel_scan.warnings` 是孤字/折行几何候选(不拦截)——**必须逐条人工过目**并在交付汇报中回应:真孤字 → 收字号/字距保单行,合法弱化副条 → 说明后放过;
- `qc.centroid_scan.violations` 非空 → build 输出质检单后退出 1:信息帧墨迹重心严重偏离收工带 900~1000(定标 940,纪律 23;**版式定标不追存量老片:复跑被拦属预期,报出来比静默好,修否自决**)——按 frames 里的重心值与方向检查信息区整体下移/上移后重渲染;
  - warnings 为轻度偏离(820~1080 外缘内),不拦截但须修正后复检;封面/封底/CTA 帧是豁免帧不参与判定;
- `qc.timeline_gate.violations` 非空 → build 输出质检单后退出 1:场景词排 `data-duration` 与配音 wav 实测偏离 >±0.3s(画面先于配音结束=尾句截断风险;画面拖过=帧尾静悬)——按 `svf timeline --apply` 重排(一条命令四处同步,可先 dry-run 看补丁);
  - warnings(相邻条重叠/乱序/条数不符/单条缺声明)不拦截——**逐条人工过目**并在汇报中回应;自查重叠时**判定必须带 ε≥1e-6 容差**(浮点残差~1e-15 不是真重叠,口径不得严于内建闸 0.3s);
- `qc.frame_check.violations` 非空 → build 在 render 前退出 1(**render 未执行零渲染费**):渲染前帧量测闸拦下压叠(垂直堆叠块负间距——「注压卡」「字压字」)与溢出(文字块出最近着色容器/出画面),violation 条目含帧名/两块 selector/数值,按报文修帧后零参数重跑(tts cached 不计费);
  - `status:"skipped"`+reason=`render_cached`(全 cached 正常态)/`chrome_pending`(chrome 尚未下载,首次 build 会自动装,装后重跑即得全量闸)/`render_base_missing`(渲染地基未 bootstrap)→ 未量测不拦,但**降级场景下溢出/压叠抽检回到一级**(红旗清单口径);
  - warnings(0~16px 紧排候选/孤字窄块候选)不拦截——**逐条人工过目**并在汇报中回应,卡内合法紧排说明后放过,全文可 `svf framecheck --project <d>` 复跑查看;
- `audio.loudness` 是**终检判定值**(两遍归一后对成片的实测),达标判定唯一口径,目标 -14 LUFS / TP -1.5 / LRA 4.0,超出容差 → 读 references/lufs-ffmpeg.md 排查;`audio.voice_baseline` 是归一前人声轨基线(普遍 -21~-23),仅供诊断,**禁止用它判定达标**——有 Agent 拿基线值误判「到不了 -14 是常态」的实测案例;
- `audio.bgm.looped=true`(mix stderr 同步告警)→ BGM 源时长不足已自动无缝循环补齐,成片不受影响但**建议向用户说明并换更长 BGM 源**;`qc.bgm_coverage.warnings` 非空 → 某人声间隙段能量比基线低 ≥10dB(BGM 中途掉的兜底观测,**告警非硬拦**),逐条看时间点定位排查;
- `audio.bgm.mode="silence"`(qc/mix JSON 同现)→ **禁止直接交付**:必须向用户说明原因,并默认补底乐(模板默认/用户品牌 BGM)重混后再交——纯人声交付是事故不是选择(build 已在计费前前置拦截 bgm 配置断裂,走到 silence 只剩「用户明确不配 bgm」一种合法路径,须用户明示);
- check 失败 → build 点名 check 与原因,按错误修 index.html/compositions 后重跑;
- 全部正常 → 按「纪律铁律」条款的红旗清单做渲染后抽检,再交付。

> gotcha:运行模型无视觉能力(读图报错/看不了图,如智谱 glm API 纯文本通道)时,抽检**降级为人工**:用 ffmpeg 按每场景中点抽帧存成图片文件,列出时间戳清单请用户亲眼过目后再放行;工具不可用不是跳过抽检的理由(第七单 glm-5.3 读图 400 实案)。
> 复核已成片:`svf qc --project <d>` 对成片独立复跑同款质检(白屏/墨迹/重心/时间轴/孤字/响度,stdout 单张 JSON,不写 state、零计费;wav 只读测量)——评审复核、交付终检与 render 环境断裂期的权威兜底(build 出不来质检单时照出)。

## 5. 诚实边界(When NOT to use)

- 管不了选题质量与文案水平——本技能只保证生产合规,不保证内容好坏;
- 不替代人工确认文案中的数字口径、事实与引文;
- 只操作给定的项目目录与品牌配置,不越权改其他项目;
- 两个人机确认点不要跳过:probe 后填 index.html、渲染后抽检;
- 匿名统计披露:出片成功时 svf 会向软件开发者的服务器上报匿名使用统计(日期/版本/机器编号/时长/激活态/安装渠道;激活态=已激活机上报码哈希前缀,不含码明文;安装渠道=装机来源标记(skillhub/workbuddy/官网);不含文案内容与凭证)——只数数不认人,失败自动静默,不影响出片。

## 6. 交付汇报模板(每单必用)

出片完成(或中途停下)时,按以下清单向用户汇报,格式统一:

1. **环节执行**:每个环节 ✅/❌ + 失败原因;被绕过的环节标注「绕过」及其代价(未走状态指纹/级联);
2. **QC 数字**:响度三值(I/TP/LRA)、bgm 状态;白屏扫描结论——**注明来源**(build 内置 QC 还是抽检替代,不得混淆);
3. **抽检结果**:安全区/墨迹/**压叠留白**/换行逐项结论;**framecheck 状态行必报**(全量闸过闸/降级+原因/复跑,三态其一);发现的问题 + 根因 + 修复动作 + 复检结果;
4. **产物**:成片与封面的完整路径;
5. **置顶评论建议**:与本片诉求匹配的回应钩子文案一条(四诉求配套模板见 references/content-flavor.md),供用户发布后置顶——回应承诺不占片长(涨粉指令自带「下期实测」除外);
6. **计划承诺对齐**:终稿对照自己的计划书关键承诺(标题/卖点/结构)逐项核对——计划里写了而终稿没有的,要么补回要么在此说明原因(执行漂移实案:计划有主体名大字,成片只剩场景词);
7. **待办**:如有绕过,提示「回正常环境后补跑 `svf build`」——未完成的环节会自动补跑。

> 重跑后汇报纪律:任何 build 重跑(改稿、改视觉、改配置)后,必须重新按本模板出汇报;产物时长、帧数、文件体积 MUST 从当前产物重新量取,禁止沿用旧汇报数字;汇报中的文案字数按**全部字符**口径(含英文与标点),与计费和时长换算一致,禁止只数汉字。
